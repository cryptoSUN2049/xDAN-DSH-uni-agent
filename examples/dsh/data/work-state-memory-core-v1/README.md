# Core memory course assets

520 training and 160 public-development instances generated by the versioned
`work_state/core_tasks.py` generator. `manifest.json` records content hashes and
coverage. These are controller assets, not a file to pass directly as model prompts.

- `task-index.json`: family, variant, seed, split and generation identity.
- `controller-tasks.jsonl`: complete task definitions, including private scoring truth.
- `model-visible-inputs.jsonl`: separate writer/reader input views for audit. Do not
  concatenate both views into one session; the existing stage runner enforces isolation.

Use `prepare_memory_training prepare --family work-state-v1
--course work-state-memory-core-v1` in the pinned deployment. It reconstructs,
checks and saves the course and produces training Parquet with task identifiers.
The model generates its own A/B trajectories online. Controller oracle outputs
are never student rollouts.

The first 16-step run is a bounded engineering diagnostic; it does not consume all
520 tasks. Repeated rollouts do not add independent tasks. The public development
split is not a sealed generalization benchmark. See the worktree goal and handoff
for actual GPU execution and learning results.
