01 / 项目定位

把可执行的 Agent 接进可审计的训练闭环

当前 Uni-Agent 是 Agent 执行与强化学习的集成层：上接任务、工具与 Harness，下接模型推理服务和 verl 训练引擎。本仓在上游基础上增加了 DSH adapter、严格训练准入与 v3 smoke 证据工具。

执行层已具备

可以组织多轮工具执行、代码任务、长文本问答和外部 Agent；每种实际组合仍受依赖、环境和协议约束。

训练底座已贯通

DSH → Gateway → 评分 → 训练曾有真实 v2 参数更新与独立 reload。新严格合同和新版本仍需新运行验收。

效果闭环尚未证明

未找到当前版本的独立配对收益证明；Harbor × DSH、跨会话记忆、自动 Harness 晋升也未形成完整闭环。

定位依据 [R4] [R5] [R9] [R25]。本文的“已实现”描述源码；“历史运行”描述既有记录；二者均不自动等于当前组合已验收。

    04 / 已打通什么

    执行、模型轨迹、评分和参数更新之间的连接

    连接代码中的实际行为证据等级 / 限制
    ① Task → Agent → 环境TaskRunner 构造 Task，初始化 sandbox / Agent，注入本任务的模型配置，执行与清理。[R6] [R9]代码实现；DSH v3 episode staging 仅支持 local。
    ② Agent → Gateway → 模型外部 Harness 可重定向兼容 endpoint；DSH runner 使用官方 SDK，把模型请求送入实际 Gateway session。[R7] [R9] [R10]代码实现；不是任意不透明远程 API 都能提供训练所需 token / logprob。
    ③ 多轮交互 → token chainGateway 保留模型生成 token 与上下文 token 的区别；上下文压缩或子 Agent 分叉可形成新 chain。[R8]代码及针对多 chain 的 CPU 测试；不等于自动压缩策略、共享记忆或完整多 Agent 协同产品。
    ④ Task / verifier → 可信奖励DSH 执行独立 verifier 命令，绑定任务、trace / artifact hash、会话及 fresh receipt，返回 typed TaskResult；完成状态与得分分开。[R11]独立命令在同一 sandbox 中执行；逻辑独立不构成权限隔离。
    ⑤ 轨迹 + 奖励 → TQFramework 关联身份、训练 token 与奖励，检查 DSH lineage / group eligibility，再输出可消费样本。[R5] [R12]新版本保留严格准入；奖励由 Framework 处理，不再通过 Gateway reward HTTP 回传。历史 v2 run 不可追认。
    ⑥ TQ → verl → checkpointTrainer 从队列取批次，计算 advantage / loss，更新权重并保存；DSH 有 GRPO / LoRA 启动和 reload 脚本。[R4] [R15] [R25]历史真实运行记录；不是当前新版本验收。
    ⑦ 新权重 → 独立能力比较有 reload 运维路径和 holdout 规划。[R25]历史独立 reload 有记录；P5 paired uplift、P6 自动演化尚未完成。
    两类 trace 不能互相替代：DSH semantic trace 回答“Agent 做了什么”；Gateway token trace 回答“模型实际生成了哪些 token”。训练以真实模型输出为基础，不能从语义事件补造 token 或 session。

    06 / 与 verl 的关系

    Uni-Agent 接管 Agent rollout，verl 承担学习引擎

    两者是上层执行框架与底层训练引擎的依赖关系。本仓通过 Git submodule 引入 verl，并实现它的 agent_loop_manager_class 扩展合同；不是再实现一套优化器。

    Uni-Agent 负责什么

    运行用户已有 Harness，组织任务和环境，把文本协议请求变成可追溯 token chain，协调评分与严格准入，向训练队列提交样本。

    verl 负责什么

    管理 rollout 推理与训练资源，消费批次，计算 advantage / policy loss，执行反向传播和 optimizer step，保存 / 恢复参数并同步推理权重。

    verl Trainer / Rollout scheduler
  → AgentFrameworkRolloutAdapter.create(config, llm_client, ...)
  → Ray AgentFrameworkWorker → GatewayAgentFramework.generate_sequences
  → TaskRunner + Gateway session + task verifier
  → 合格 trajectories → TransferQueue → ReplayBuffer
  → verl advantage → actor loss → optimizer step → checkpoint
  → 更新后的 policy 继续生成下一批轨迹

    适配器的 generate_sequences() 是异步提交；generate_sequences_and_wait() 为独立推理提供等待入口。训练数据通过 TQ 交付，不是把自然语言最终答案直接返回优化器。[R4] [R5]

    训练方式底座能力与本项目接线当前判断
    GRPO / LoRADSH 脚本有具体配置；历史 v2 参数更新与 reload 有记录。[R15] [R25]本仓最接近完整闭环的路径；仍须重做合格的新版本实验。
    PPO / GSPO / DAPO 等verl 提供多种算法或 recipe；通用层可复用。算法存在 ≠ DSH 已跑通。DSH DAPO 同预算对照、动态补样总预算仍属后续验收。
    同步 vs 全异步DSH 使用 V1 sync；通用 recipes 有 separate_async / colocate_async。[R15] [R19] [R27]异步模型请求、异步任务执行、异步训练是三个不同层面。
    SFTverl 有独立监督训练实现。还需要本项目的 DSH 数据转换、训练 mask、数据资格及 reload 评估配方。
    OPD / teacher policy当前 Adapter.create 在 teacher_client 非空时抛 ValueError。[R4]明确未接通，schema 中 teacher 字段存在不代表教师调用已实现。
    FSDP / Megatron / 推理后端属于 verl 资源与训练执行层；DSH 当前配方选择其中的具体组合。本页不承诺所有后端 / GPU / 模型组合兼容，尤其不把新 verl checkout 当成通过。
    新版本已完成奖励职责迁移：TaskRunner 返回 typed TaskResult；Framework 保护 DSH verifier_reward 与谱系、协调奖励并写入 TQ。Gateway 已移除 reward_info HTTP endpoint，集中负责会话与 token。历史 schema1 审计保留读兼容；当前 schema2 和 typed 字段仍需通过新真实 run 检验消费合同。[R5] [R6] [R11] [R12]

    底层真实执行点：verl V1 Trainer 消费批次并更新 actor，FSDP engine 执行 backward / optimizer.step。[R36] [R37] [R38] 这些引用取自配对版本 fefb080。

    官方职责核对：通过 Context7 获取 verl Agentic RL 文档、扩展接口、Trainer 文档。官方 main 用于解释分工，本项目可用性仍以固定版本源码为准。

    07 / 数据和信任边界

    正确的训练样本必须同时有行为、token 和资格

    对象 / 接口至少承载什么谁产生，谁负责验证
    任务 seed / episodetask identity、instruction、fixture / runtime 身份、配置和预算。数据准备与 operator 控制；seed 本身不证明真实执行或训练资格。
    Gateway session / chain实际会话、token IDs、response mask、logprob、policy version；多 chain 与任务对应。Gateway + 模型推理端产生；Framework / auditor 检查形状、值与身份。
    DSH semantic trace工具、插件 / 能力变更、失败恢复、清理等真实事件及 hash。DSH runtime 产生；用于行为和完整性验收，不能代替模型 token。
    typed TaskResult / verifier receiptfinished、可信 reward、task / session / rollout 关联、freshness、trace / artifact hash。Task / 独立 verifier 命令产生，Framework 检查；新版本已采用 typed 结果合同。
    训练 group / consumption候选集合完整、eligibility、一致 task / group 身份、实际 trainer 消费记录。Framework 准入 + TQ / ReplayBuffer + 事后审计；旧 run 缺失 crosswalk 不能补造。
    Checkpoint / 独立评测base 与 adapter 身份、训练状态、reload 结果、固定 holdout 与预算。verl 保存；独立评测过程判断是否改善能力，不靠训练 loss 自证。

    有效失败也有学习价值

    完成了任务协议且证据完整、安全，但策略没成功，可以 eligible 且 reward=0；否则只能学习到“永远挑成功样本”。

    未完成和证据问题必须拒绝

    unfinished、错配、重放、篡改、不完整 group 与不安全轨迹不能仅设 reward=0 后混进正常训练统计。

    合同以源码 [R5] [R11] [R12] [R14] [R30] 为准。哈希和新工作目录提供完整性检查，不是同 UID 对 verifier / fixture 的不可修改隔离。模型请求的逐轮 token 上限也不等于整个 episode 或 refill 循环的总成本上限。
    当前 typed 合同另有三道代码保护：TaskResult 禁止 metadata 覆盖保留字段；Framework postprocessor 禁止改 finished / reward / DSH receipt；strict verifier 模式禁止 custom reward worker 替换可信奖励。

    08 / DSH 的实际能力

    已有训练适配与行为验收，熟练度仍需独立证明

    DshAgent 通过 runner 调用外部 deepseek_harness SDK；DSH 拥有运行循环和插件语义。本仓负责模型 endpoint、配置、trace 收集、评分和训练关联。不能把这份 Python adapter 当成 DSH runtime 全部源码。[R9] [R10]

    八类 v3 行为期望检查
    runtime-grounding先检查真实 runtime 能力，再采取动作。
    lifecycle-composition组合能力，并处理它们的生命周期。
    multi-step-configuration多步骤配置、更新与后续操作对应。
    diagnostic-recovery面对错误诊断并恢复执行。
    timeout-cleanup超时 / 取消后的资源清理。
    permission-abstention无权限时停止或拒绝越界操作。
    reward-hacking-resistance保护评分边界，拒绝不合格证据。
    transfer-composition在另一任务组合中复用能力。

    目录、fixture、live verifier、执行监督和 TQ 审计已存在。许多 smoke prompt 提供明确代码或操作序列，因此首先检验执行与证据合同，不能据此宣称模型自主掌握了八类能力。M1 smoke 的训练资格刻意保持 false。[R13] [R14] [R22] [R23]

    09 / Harbor 与 Modal

    已有两种环境路径，DSH bridge 是实际缺口

    原生 Task 路线

    Uni-Agent Task → Uni-Agent Sandbox → Agent。选择 Modal 时由 ModalSandbox 创建环境；已有 exec / 文件操作，端口暴露接口尚未实现。 [R3] [R17]

    Harbor Task 路线

    HarborTask → harbor trial start → Harbor Environment → Harbor Agent。sandbox 字段要求 None，Harbor 自己管理 Docker / Modal 生命周期。 [R16]

    HarborTask 返回普通 reward / accuracy，代码明确用于 evaluation。它把 agent 名称交给 Harbor，agent.name=dsh 不会自动触发 Uni-Agent 的 Agent registry。已有 oracle 配置也不等于真实 oracle 已执行。

    接通 DSH × Harbor 要补什么完成标准
    Harbor-compatible DSH bridge在 Harbor 已有 Environment 中运行 DSH，复用 exec / 文件能力，不二次创建同一任务 sandbox。
    实际模型网络路径沙箱内能访问带认证和 session 路由的 Gateway；注入 URL 本身不建立隧道，localhost 指向当前沙箱。
    结果与训练资格映射Harbor task / trial / reward 与 DSH trace / receipt、Gateway session / chain 严格关联。
    分布式路径和 runtime 身份worker 有固定版本任务包与可复建 DSH runtime；开发机绝对路径不可直接复用。
    当前 strict 限制的适配strict CLI 限定 dsh_architecture，episode staging 限定 local；桥接后需单独验证完整合同。
    完整验收先 Docker 单任务，再 DSH / Gateway / receipt，再真实 update + 独立 reload；Modal 属另一个环境组合。

    本次没有运行 Harbor oracle 或 Modal 任务。现有交接的 H0 未完成记录 [R26] 与桥接代码缺口一致；本页不声明当前云端资源状态。

    10 / 对原始目标的审慎挑战

    应当评估结果，而不只统计支持多少框架

    打通训练 ≠ 已提升能力

    真实 optimizer step 证明参数改变，reload 证明权重可用；只有固定预算下的配对未见任务实验，才能证明这次改变更有用。

    模型学习 Harness ≠ 自动改造 Harness

    前者是在固定 runtime 内学习选工具、组合能力、处理上下文；后者修改并晋升 Harness 代码 / 配置。两个变量混在一起，会无法归因收益。

    记忆机制 ≠ 跨会话产品能力

    MemAgent 可以提供训练思路和多 context 轨迹复用，但持久记忆还需要检索、生命周期、来源和权限，以及跨任务评估。

    基础设施更丰富 ≠ 闭环更快

    若目标是证明 4B 更懂 DSH，现有原生路径已最接近终点。Harbor 服务于标准化任务，Modal 服务于环境扩展，不应都成为首次效果验证的前置。

    建议的架构取舍：保留 Uni-Agent + verl 训练底座，用薄适配补缺口。先固定 Harness 验证模型学习，再冻结模型测 Harness 候选收益，最后才研究联合演化。这样能判断提升来自哪里，也能更早停止无效投入。
