01 / 直接执行

应该包括这些手段，但它们分属三个不同维度

推荐主线：可验证任务与数据底座 → SFT冷启动 → 学生访问状态上的蒸馏／纠错 → 在线任务RL → 逐步增长的Agent长循环与跨Session RL → 专家整合与发布。

维度包含什么关键区别
监督来自哪里示范token、teacher概率、独立任务rewardSFT/GKD/奖励优化可以作用于同一种任务；不是不同数据仓库。
样本由谁、何时生成固定示范、teacher rollout、当前student rollout、历史student replayon-policy描述采样与当前策略的关系。学生曾经生成过，不代表现在仍是on-policy。
任务跨度单步、多工具、多context、多Session、长程目标Agent long-loop RL是环境与时间跨度，不是与GRPO/PPO并列的某个固定loss。
GKD和on-policy distillation不是两个必须顺序跑的阶段。GKD是包含不同采样分布与散度的蒸馏框架；用当前学生生成数据的GKD就属于on-policy蒸馏。具体实现还要区分直接分布匹配与policy-gradient蒸馏，不能仅凭名字认定等价。GKD原论文

本专题是在前一版完整专项方案上的数据与训练深化，所有新增数据合同、路径与规模均为建议。本轮只审计和设计，未训练或改产品代码。

03 / 优先补齐的环节

先接通九个断点，再决定增加算法复杂度

顺序缺口与交付谁负责／如何验证
1可执行Task Factory：任务、初态、工具目录、结束条件、verifier与reset独立封装。DSH拥有环境，Uni-Agent拥有Task adapter；同seed重建、目标可判定，teacher不能接触oracle文件。
2统一身份和资格：task→attempt→phase→decision→artifact→token→update。复用DSH source与Gateway ledger，用crosswalk联结；不建立第二份“更可信”的自造日志。
3SFT compiler与mask：真实pre-request＋正确动作目标。CP compiler提供语义source；Uni-Agent release builder对齐Qwen3.5 template、mask和重复prefix权重。
4学生错误状态采集和教师纠错：不只保存teacher成功路径。从学生实际失败前状态取样，保留恢复轨迹；把tool调用与实际下一request对应。
5Teacher scoring接口：文本示范／动作建议／token概率分别建类型。选定teacher revision及服务能力；不把批评分、logprobs开关或生成结果冒充任意prefix token scoring。
6终态和奖励：策略失败、业务预算终止、基础设施故障分别处理。Task/verifier和严格准入联合验收；不把unfinished修改成finished以绕过门禁。
7跨context／跨Session全链训练：A写、B读、B完成能更新A的决策。一个冻结policy下的完整candidate；全部有资格模型动作保留，广播终奖先作基线，统计链长偏置。
8可恢复环境和credit：长程顺序执行先通，关键节点分支再接。reset支持普通长循环RL；动作前checkpoint/fork是CP分支的额外条件，不该阻塞所有顺序RL。
9效果归因与发布数据：权重、Harness、教师、预算分别冻结。同DSH的MiniCPM对照＋公开Harness迁移＋端侧成本；sealed test不可参与选checkpoint。

05 / 数据生产与课程

以可执行任务为中心，同时积累成功、错误状态与恢复

数据产品来源与制作方式主要用途／验收
D0 · 能力与工具快照DSH实际catalog/schema、必要README与技能说明，随runtime版本冻结；变化事实仍通过检索和工具提供。示范提示与任务生成；不把背代码目录当DSH执行能力。
D1 · Verified demonstrations强teacher在同DSH权限/环境中执行，或专家手工构造后真实重放；保存行动、观测与最终验证。SFT合法动作和基本策略；简洁可用的解法优先，长thinking不是质量标准。
D2 · Student mistakes + repairs当前student rollout采集；在真实错态上请求teacher下一动作/短恢复段，重新执行验证。最先弥补SFT分布偏移。在SFT／纠错视图中，原错误作为输入历史mask0，正确修复作为目标；需dataset显式采用目标mask。RL视图保留合法失败候选及其动作，通过reward/advantage学习，不能套用此屏蔽规则。
D3 · Memory lifecycle chainsA探索/选择写入；B fresh Session按任务主动找回；后续加入事实变化、冲突、撤销与干扰。记什么/不记什么、何时读、更新、忘记、scope隔离；最终任务结果而非摘要长度。
D4 · Context decisions保留/压缩/移出/回源的状态变化；记录操作前后实际request与保护事实。自主context策略；编辑无必要的任务也是重要负对照，防止总是压缩。
D5 · Online task pool冻结任务版本与verifier，按当前checkpoint估计难度，在线生成新group。RL/OPD的输入是任务池；训练数据随策略变化，不是一次性固定答案CSV。
D6 · Branch / causal probes可恢复节点的平行continuations、memory替换/遮蔽对照、真实后代终奖。CP credit与记忆依赖诊断；对照实验的隐藏结果不进入学生观测，分支只取可恢复环境。
D7 · Regression & sealed tests按文档来源、repo/issue、任务family、A/B全链分割；公开数据做去污；预留新故障/新工具组合。发布门槛；定期补新sealed分布，不能只对训练模板换几个变量。

生产流程

  1. 来源登记与许可／去污 → 先分split → 构造TaskSpec和独立verifier。
  2. teacher/student校准，验证题目可解且目标清晰；如果所有候选都错，先检查环境与评分，不能默认模型不行。
  3. 真实执行，采集所有attempt；分别评定完成、正确、轨迹完整、用途资格。
  4. 挑选高质量示范与代表性错误状态；重复样本按任务family归组；固定release后构造训练视图。
  5. 训练后用validation检查失败分布，补充新的任务/恢复数据，再进入下一轮；sealed test不回流。

首批规模建议：先证明信号，再放大

批次建议规模（规划，不是现有库存）进入下一批的条件
T0 · 管道验证约32个工程任务，覆盖工具、恢复、memory与context；少量SFT行＋2个有效group＋一次reload。证明数据/梯度/权重链，不报告泛化提升；工程题不转成正式test。
T1 · 首轮能力试验300—600个独立训练任务，每题约2—4条有效示范/恢复episode；另设约100个难度校准、100—150个validation、300—500个封存test任务。数值只是启动规模；family覆盖与paired方差决定检验力，不能用episode展开数替代任务数。
T2 · 有收益后扩展约2k—5k训练任务；逐checkpoint刷新学生rollout与纠错；按已验证收益逐步增加工具组合和长循环。扩数据前先确认数据质量/teacher成本/每有效group成本；不直接复制50万条外部trace。

示范数据初始配比可按有效目标token设为：工具执行25%、恢复15%、记忆20%、context20%、跨Session10%、通用回归10%。这只是起点；给长轨迹设权重上限，按validation重分配。RL任务池按任务成功率、family与长度分桶，不沿用SFT行数配比。

预计训练量必须由真实tokenizer计数：例如1,000条episode × 平均4,000个目标token，仅目标就约4M token，teacher打分还要读prompt和observations。窗口重叠、group采样、失败重试与分支会进一步增加算量；预算不能只填“样本数×epoch”。

06 / 训练手段与依赖

SFT、GKD／OPD、RL如何各司其职

方法针对的障碍数据和teacher要求建议位置
SFT / sequence KD不熟悉合法动作、工具约束、信息表示与基本恢复。真实示范或经过验证的teacher文本；目标动作mask。跨tokenizer可重新tokenize文本。必做冷启动；少量高质量短路径，混入恢复和通用回归。
学生状态纠错模仿teacher理想路径覆盖不到学生常犯错后的状态。student真实访问状态＋teacher纠正动作/短后续；需要真实执行验证。只返回文本的API也能做。SFT后尽早做，通常比先搭完整logit服务成本低；明确命名为纠错模仿，不冒充token-GKD。
On-policy GKD / direct distribution loss需要在学生常走的prefix上获得密集teacher监督。当前student生成；teacher对同一因果prefix给可对齐概率；锁定散度/混合采样比例。teacher scorer与token对齐通过后开启；沿用当前verl组件补Uni-Agent bridge。
Policy-gradient OPD用teacher与student的概率比形成密集优化信号。真实学生生成token、old/student/teacher logprob、明确梯度与mask、policy freshness。与direct GKD是独立loss variant，先分开对照；不能把所有“KL”当相同更新。
任务级RL（先GRPO基线）示范会模仿，但真实完成率、恢复、记忆取舍不佳。可验证任务、完整candidate group、真实rollout和任务reward；不强依赖teacher。可与蒸馏桥并行准备；有合法动作且任务存在学习信号时即可开始。
Agent long-loop RL早期工具/记忆/context决策影响几十步甚至B会话的结果。整条episode/chain、预算和终态、全动作mask；进阶分支/critic需额外合同。不是最后附加一个长prompt；在任务跨度上逐步提升，短窗口内也能做长程任务。
多专家整合／最终蒸馏工具、记忆、长程RL专家各有长处，希望发布单模型。经独立验证的专家checkpoint与任务路由，覆盖学生访问状态的迁移/蒸馏数据。后期可选。不要先把单卡资源拆成一组未经验证的专家；现有OPD桥通过后再复用。

原始依据：GKD与OPD方法说明。本地实现将两种更新方式显式分开，并拒绝部分错误loss组合。[U6] [U8]

当前最容易踩的坑：云端API能生成答案、能返回它自己生成token的logprob，仍不代表它能对学生指定的完整token序列作teacher forcing评分。直接token分布蒸馏必须验证这个能力；否则先走文本示范/学生状态纠错。

07 / Teacher与token合同

先决定能拿到什么信号，再选择蒸馏实现

teacher能力可以做不能直接做
只有文本生成示范SFT、学生错态修复、结构化行动建议；输出可由独立verifier重跑。不能重建完整next-token分布；自然语言“这步很好”不是token logprob。
给定学生prefix的实际token logprob在序列/词表/位置严格对齐后，构造sampled-token OPD及对应估计器。不等于full-vocab或top-k分布匹配；稀疏top-k缺失token不能随意填0或负无穷。
给定prefix的top-k或full distribution明确截断质量/缺失概率处理后做相应KD loss；同词表更易复用当前实现。不同tokenizer下同一个整数token ID不代表同一文本，不能直接KL或截断词表拼接。
跨tokenizer大teacher文本层蒸馏/纠错优先；专用cross-tokenizer分布对齐作为单独方法验证。同一家族名称也不保证词表、special tokens和chat template一致。

当前verl teacher manager直接接收student sequence_ids并取prompt logprobs，因此要新增显式兼容性检查，而非假设实现会自动发现所有词表错配。评分只基于该decision当时的真实可见prefix；不能把后续工具结果、B会话答案或隐藏oracle拼回早期teacher输入后，当成同观测蒸馏。[U5]

  + teacher_revision + tokenization_profile + signal_type

将示范teacher、概率teacher、独立verifier分开管理。特权teacher可以辅助设计数据或识别错误，但学生动作仍必须可由学生当时能看到的信息执行；用于训练的特权信息须单列用途，防止记忆任务被答案泄漏“解决”。

单GPU现实选择：先离线生成并缓存验证过的示范/纠错，训练阶段卸载teacher。真正OPD要持续刷新student状态；teacher可分时加载或用独立服务，记录排队与额外算力，不能假设一个大teacher＋student训练＋rollout都能同时装入当前卡。缓存必须随policy/decision/prefix身份管理，不能无限复用旧学生轨迹并继续称on-policy。

08 / Agent long-loop RL

训练跨动作的后果，不只是把context开到128K

跨度课程示例要验证的新增环节
L1 · 2—6次决策发现工具→调用→检查结果；4—8K活动窗口可作起点。每步合法、真实settlement、任务终态可判定。
L2 · 6—15次决策工具失败→诊断恢复→继续；夹杂不应修复的正常任务。错误状态覆盖、无效重试成本、正常任务不被误修。
L3 · 15—40次决策超过活动窗口的信息流，需选择记忆、压缩并回源；窗口可控制在8—16K。context editing实际改变下一request；较长episode不是靠无限扩大窗口。
L4 · A→B多SessionA探索并写记忆；B不能访问旧transcript，只凭允许transfer完成目标。same-candidate/same-policy、完整A/B token账本、读回与奖励回传。
L5 · 40—100+次决策及组合较长工具工作流、动态事实、记忆更新与多次handoff；再按瓶颈扩窗口。恢复/总预算/尾部失败；耗时、token、工具副作用和有效成功率一起报告。

这些长度是拟议课程档位，不是项目已实现上限。决策数、模型请求数、工具调用数、context长度、Session数应独立记录。

信用分配按证据递进

  1. 全链终奖基线：同candidate的A/B动作使用最终可验证结果，先证明A写入策略能接收梯度；非零梯度只是工程通过，不证明记忆有用。多chain不能让“多写几个segment”无意获得更大样本权重；记录candidate/chain/token各层归一化。
  2. 诊断拆分：分别记录memory有用事实、B读回、过期修正和最终成功；诊断指标不立即变成reward，避免模型为“多读/多写”刷分。
  3. 可验证子目标：确需dense reward时，锁定独立子目标或有理论约束的shaping，并做终奖-only对照；教师语言评价不能替代环境完成事实。
  4. ContextPilot：从动作前真实checkpoint有界fork，用后代terminal结果估计snapshot价值；同query uid分组并处理共享prefix。普通顺序长循环RL无需等待这一步。[C4]
  5. Token critic：在基线成立后另测value／GAE、长度自适应与校准；不要把critic和CP子树均值当同一种credit，也不要初次就同时改变所有机制。

终态与恢复必须单列合同

task_success / task_failure / budget_exhausted / model_length_limit / tool_timeout / runtime_error / cancelled / evidence_invalid保留原始reason。当前DSH strict继续拒绝unfinished。若希望学习“在业务时间内未完成就是失败”，应先把可验证预算耗尽定义为任务MDP的正式终态，并单独验收；基础设施截断仍是不同类别。不能把token-limit轨迹改个finished字段送入训练。

reset重建任务初态，resume续同attempt，fork复制动作前隔离状态。后者需要Session/projection/memory/文件/权限/工具pending state等一致；纯ActorFS任务先行，不能靠JSON snapshot回滚网络写入或宿主进程。所有fork共享不可回滚的全局采样与墙钟预算。

10 / 我的判断

我们缺的首先是可学习的经验，而不是更多算法名称

第一，DSH熟悉度不能只用README问答衡量。模型应学会查实际工具目录、遵循约束、从失败恢复；版本变动的参数/项目事实通过检索和runtime提供。小规模领域继续预训练不是首轮必需，先比较检索＋few-shot、SFT与任务训练。

第二，最稀缺的是学生失败后“应该怎样继续”的数据。优质teacher完整成功轨迹值得保留，但初期更可能快速见效的是错误状态覆盖和短恢复示范。否则SFT做得越漂亮，实际运行时一次偏离就越容易失控。

第三，强记忆应能少写、会更新、知道不该读。只奖励文件存在、摘要短或读取次数，会培养错误习惯。数据必须包含无须记忆、旧事实失效、信息冲突、撤销和干扰，并最终看任务完成。

第四，长循环RL应从现在的数据设计开始，训练难度逐步提升。Task/Decision/Memory身份如果今天只考虑单Session，以后补跨Session credit代价很大；但没有必要今天就购买大teacher、开128K窗口或实现完整树搜索。

建议下一批具体成果：统一数据schema和一份真实可复算release → Qwen3.5可验收的SFT小闭环 → 同一批任务上的学生错态纠正与GRPO对照 → A/B记忆整链训练。teacher token-scoring桥并行设计；在结果证明需要更密集信号时接GKD／OPD，随后扩长循环与CP credit。
