01

四个核心目标，逐级拿证据

“把系统跑起来”和“把模型训强”需要不同证据。每一级通过后再扩大实验，避免用训练 loss 下降代替能力提升。

G1 / 工程闭环

采样 → 评分 → 更新 → 恢复

用最小任务完成一个真实训练 batch；保存状态与采样权重；新进程加载后还能继续解题。

验收：真实 API 回执、轨迹、更新证据、checkpoint URI、独立 reload 报告。
不等于：模型能力已经提高。

G2 / 信号可信

Teacher 评分正确，任务奖励可靠

确保每个参与训练的 token 得到正确条件下的 Teacher logprob；正解通过，空操作失败，grader 故障不冒充低分。

验收：多轮 golden trace、token/mask/shift 对齐、oracle/nop、任务分割审计。
不等于：一个文本 prompt 通过就覆盖所有工具场景。

G3 / 能力提升

同预算下，9B 超过自身基线

比较未训练指令版 9B、OPD、RL、hybrid；在独立验证任务上检验成功率、稳定性、每道成功任务成本。

验收：配对任务结果、多个随机种子、置信区间和失败分类。
决策：只有持续改善才扩大数据、轮数与上下文。

G4 / 外部对照

检验能否超过 Opus 4.6

锁定 Terminal-Bench 版本、Agent harness、工具权限、token/时间预算及重试次数，再运行一次预先定义的最终对照。

验收：可复现的完整评测报告及不确定性。
边界：Teacher 更强或参数更多，不保证 Student 达到该目标。

建议的最短路线：以指令版 9B 开始，优先利用已有工具能力。先走 Tinker 27B Teacher 闭环；只有实验证明 Teacher 是主要瓶颈，再讨论更大模型、自部署评分或额外 SFT。

03

一个训练 batch 的完整流程

  1. 锁定输入

    读取配置和任务版本；选取一组训练题；固定本批 Student checkpoint。

  2. 创建任务环境

    Harbor 载入指令；Modal 按任务镜像创建隔离 sandbox，每条 rollout 独立执行。

  3. Student 自己尝试

    模型生成 thinking、bash 调用或答案；执行工具并返回 observation，直到结束或到达上限。

  4. 得到任务分数

    运行 verifier；区分任务失败和基础设施故障。收集原始 token IDs、logprobs、mask。

  5. Teacher 逐 token 评分

    将 Student 实际上下文与动作序列送入 compute_logprobs；对齐每个训练目标 token。

  6. 合成学习信号

    任务奖励减组均值得到 RL advantage；再叠加负 β × sampled reverse-KL。

  7. 更新与保存

    Tinker 执行 forward_backward 和 optim_step；消费回执，保存 checkpoint，记录指标。

  8. 刷新与检验

    创建新 sampler；回收 sandbox；下一批使用新权重。指定里程碑做独立 reload 与后评估。

“On-policy” 的关键：训练轨迹来自本批 Student 策略。初期使用同步批次，每次更新后换新 sampler；跨批复用旧轨迹或旧 sampler 需要额外的策略版本与 off-policy 校正设计。

04

同一套系统，比较三种学习方式

切换下面的模式查看信号来源。默认使用官方 importance_sampling policy-gradient loss；这里的 OPD 是对 Student 采样 token 的 reverse-KL 估计。

HYBRID / 任务反馈 + 教师指导

学会成功完成任务，也参考 Teacher 的每一步判断。

Aᵢ,ₜ = mᵢ,ₜ × [(Rᵢ − mean_group(R)) − β × (log π_old − log q_teacher)]

Harbor 提供任务是否成功的稀疏奖励；Teacher 提供动作 token 的密集反馈。所有同组轨迹分数相同时，RL advantage 为零，OPD 仍可能提供学习信号。

严格评分究竟要求什么

给定 Student 已经生成的动作 aₜ 及此前上下文 hₜ，取 Teacher 的 log q(aₜ | hₜ)。Teacher 必须对指定序列做 teacher-forcing；返回 Teacher 自己生成答案的 logprobs 不满足这一要求。

本方案可调用 Tinker 的 compute_logprobs_async(ModelInput)。评分覆盖上下文，但训练 mask 只选择 Student 动作。

“严格”不等于全词表精确 KL

目标形式是 E[a~π][log π(a|h) − log q(a|h)]。我们只在 Student 采到的动作上估计，因此不要求 Teacher 返回全词表 logits，也不是用 top-5 概率补齐分布。

单 token、单轨迹或单批估计可能为负。Teacher KL 下降也不直接证明任务成功率提高。

模式任务 rewardTeacher 信号回答的问题
OPD任务主 reward 设为 0β > 0Teacher 指导单独能带来多少提升？解析失败/超长等环境惩罚仍可能存在。
RL真实 verifier rewardβ = 0只依靠成功/失败反馈能学到多少？当前入口仍检查 Teacher，可在后续消除该依赖。
Hybrid真实 verifier rewardβ > 0两种信号是否互补，能否超过各自单独训练？

公式描述默认 kl_discount_factor=0、二值 mask、组内减均值的情形。若启用未来 KL 折扣，信号传播会变化，必须作为独立实验记录。OPD 与 RL 不必强制先后串联；优先比较三种模式，再根据结果考虑“OPD 热身 → RL / hybrid”。

真正决定训练正确性的接口契约

先保留原始 token，再讨论损失函数

system + user上下文 · mask 0
Student thinking模型生成 · mask 1
Student tool call模型生成 · mask 1
tool observation环境返回 · mask 0
Student action / answer模型生成 · mask 1

示意按 token 来源划分；具体 role delimiter、EOS/stop 和追加标记需按 renderer 与真实采样边界核对。对已经生成的序列不要 decode 后再 encode，也不要只保留用户看到的 final content。

边界目标契约 / 需要保存的字段失败处理与后续覆盖
任务 → rollout任务 ID、revision/hash、split、镜像信息；Student checkpoint、renderer、采样参数。任务缺文件、split 重叠先拒绝；训练前执行 oracle/nop。
rollout → 评分精确 input_ids、生成边界、每轮 observation、Student logprobs、action mask。缺失/错位直接阻断该批；不能将 Teacher 输出替代 Student action。
Teacher → advantage长为 N 的序列得到 N 个位置评分；首 token 通常无前文可评分。动作位置必须非空、有限且有效。Teacher/Student 词表 ID 与分词行为检查；不能仅凭长度相等放行。
序列 → Datuminput=tokens[:-1]、target=tokens[1:]；Teacher 分数也取 [1:]；mask/logprobs/advantages 同目标对齐。多轮 golden trace 验证 N/N−1 边界；环境 token 的训练贡献必须为零。
梯度 → optimizer记录 loss 配置、step、模型版本、有效 token 数；await 提交后还需等待返回的 APIFuture。NaN、缺失评分或全零有效 token 阻断；不重复执行结果未知的更新来“重试”。
保存 → 下一批区分 state_path 和 sampler_path；创建绑定新权重的 SamplingClient。不让旧 sampler 混入新批。独立 reload 另行验收。

Renderer 风险：本地模型映射中，9B 推荐 qwen3_5，27B 本轮解析为 qwen3_8_xhigh_reasoning。目前 Teacher 评分使用 Student 的原始上下文，避免位置改变；词表一致仍不能证明模板语义、normalizer 或工具状态完全兼容。必须用真实多轮轨迹验证 Teacher 在这一上下文下能提供有效信号。

实际覆盖边界：已对 P0 真实批次核对原始输入、目标 shift、Teacher 评分、action mask 和 advantage 公式；缺失/非有限动作分数及全零有效 mask 的拒绝路径有本地测试。本次覆盖 6 个 Datum、1,179 个动作位置；长序列、更多模板及通用 sample/rescore 数值容差仍待补充。

06

数据决定提升空间，评测决定结论可信度

训练课程：从能学会的任务开始

  • 文件与文本：查找、过滤、编码、格式转换。
  • 脚本与调试：修复小程序、解析报错、补齐依赖。
  • 仓库任务：构建、运行测试、定位失败、生成产物。
  • 系统与长程任务：状态跟踪、多工具组合、错误恢复。

使用授权且独立的 Harbor 格式任务。按任务族划分 train/validation/final-test，保留来源与许可。任务规模按阶段扩增，不把具体数量当作性能保证。

先判断 Teacher 是否真的能教

在同一批独立任务、相同工具和预算下测 9B 与 27B。重点看 Teacher 能完成而 Student 失败的任务及失败原因。

若 27B 也大量失败，应先检查环境、任务难度和 harness，再决定换 Teacher。若 9B 已全通过，改用更有学习空间的任务。

Teacher 参数量和通用能力只能作为候选依据，不能代替本任务基线。

集合 / 阶段用途规模建议与隔离规则
Smoke 任务验证通信、工具、grader、update 和 reload。先 2 个训练 + 2 个验证任务；只证明工程闭环，不估计泛化。
小型实验集比较 OPD / RL / hybrid 和 Teacher 边际收益。可从几十个训练任务开始；按任务族留出验证集。数据不足则先补数据，不循环少量题冒充规模。
验证集选超参、checkpoint、课程与停止时机。可重复评估，但不能训练；多次选择会对它过拟合，因此另留最终测试。
最终 Terminal-Bench锁定配置后的最终能力报告与 Opus 对照。整个研究期间不进入训练、不按它反复调参；固定 benchmark 版本与任务清单。

“超过 Opus”必须固定比较口径

区分模型权重能力比较与Agent 系统成绩比较。前者尽量固定 harness、工具、预算；后者可用模型适配的系统，但必须披露差异。不能拿自己的一次 best-of-N 成绩，直接比较别人不同设置的公开 pass@1。

  • 记录精确模型/版本、benchmark revision、Agent 代码 commit、工具权限和依赖镜像。
  • 报告每任务成功率、终止原因、样本数、随机种子、token/耗时/费用；重试和截断单列。
  • OPD/RL/hybrid 从同一初始权重出发。既报告等训练 token 的比较，也报告实际成本，避免忽略 Teacher 评分费用。
  • 对同一任务做配对比较；重复运行估计方差，按任务聚合置信区间。小样本结果标“探索性”，不写成确定超越。

P0 参数意义为什么这样设
group_size=2同题两次独立尝试最小能产生组内 reward 差异的设置；两次同分时 RL 信号为 0；本次两次均成功，已经实际出现该情况。
groups_per_batch=1每批一题训练 sandbox 并发约为 2；验证沙箱另外计算。
max_steps=1仅一批训练验证链路，不用于判断能力提升。现有 trainer 遍历一次任务，不自动增加 epoch。
temperature=1.0减少采样分布变换降低评分解释复杂度；仍需验证 logprobs 与实际策略定义一致。
3 turns / 4096 tokens限制交互轮数和单次生成功能验证预算；复杂终端任务可能被截断。最终评测另设公平预算。
LR 1e-4 / rank 32 / β 1沿用试跑级初值只作初始配置，不是适用于本任务的最优超参结论。

容易误判的一点：eval_every=1 当前是在每批更新前评估。跑完一个 batch 后仍需单独进行新 checkpoint 的评估与独立 reload，不能把更新前结果当作训练后成绩。
