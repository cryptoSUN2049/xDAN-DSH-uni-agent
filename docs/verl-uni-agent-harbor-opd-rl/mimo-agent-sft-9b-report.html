01 / 机制与证据

先看结论：继承能力，再训练执行

算法定性：SFT 监督蒸馏，不是 OPD。 教师生成示范，学生通过监督微调学习；“Distill”不能等同于 on-policy distillation。后续分域 GRPO 是另一阶段。

MiMo 为 9B 提供的是一个经过大规模 Agent SFT 的强化学习起点。它证明了值得验证的路线：已有指令模型 → 强教师任务示范 → Agent SFT → 真实环境 RL。

04 / 机制与证据

SFT 算法：把教师经验变成学生的下一步

原理解释，不是论文超参复刻

设一条教师示范序列为 x，学生参数为 θ，mₜ 表示第 t 个 token 是否参与监督。典型的 masked 自回归 SFT 为：

LSFT(θ) = − Σt mt log πθ(xt | x<t) / Σt mt

训练时用真实示范前缀预测下一个目标 token（teacher forcing）。模型因此学习在某个任务状态下如何继续推理、发出动作或交付答案。上式是一种常见 token 平均形式；MiMo 9B 的具体归一化、样本加权和 packing 实现未由 §7 完整披露。

与 OPD 的区别

SFT 通常学习离线教师示范。OPD 则让学生生成，再由教师对学生实际前缀提供分布监督。前者能提供优质路线，后者能覆盖学生自身偏离后的状态。

为何异族教师可用于 SFT

教师文本/结构化轨迹可用学生 tokenizer 重新编码，不需要教师和学生词表一一相同。工具协议、thinking 格式和信息边界仍须转换验收。

不能由此推出 OPD 兼容

逐 token 分布蒸馏需要额外解决概率坐标与模板语义。这个 9B 模型的 SFT 成功，不等于它与任意教师可以直接做原生 token OPD。

为什么之后还需要 RL：离线轨迹教学生在教师状态上做选择；上线时学生会犯错，进入示范未覆盖的状态。真实环境反馈能针对这些状态优化最终任务结果。

Thinking 应该怎样对齐

示范中的 thinking 可作为 SFT 目标，但“像老师一样写思考”不等于思考正确。采用三层验收：①格式与 mask 对齐；②行为和证据一致、没有虚构观察；③独立任务完成率与预算收益。长度不是质量奖励，公开推理文本也不能证明模型内部因果过程。

建议保留完整成功轨迹、有价值的失败后恢复轨迹；纯失败分支单独记录用途，不将错误动作无差别当正例。最终是否将 reasoning 纳入目标必须在 DataRelease 中显式声明。

把方法做成可复现的数据生产线

推荐给我们实施
  1. 先定义任务族与隔离方式。按仓库、文档集合、模板族分 train/dev/sealed，之后才生成，防止题面改写跨集合泄漏。
  2. 建立可重置环境与 verifier。保存初始文件、依赖镜像、允许工具、参考解与正负控制。任务和评分先于大规模合成。

08 / 机制与证据

GRPO：从会模仿到能独立完成

论文路径

同一个 SFT 初始化分别进入 Code、Cyber、General、Visual 的 GRPO。公开环境规模约 7k 个不同任务标识，另有约 1k 音乐生成任务支持额外实验。它们是 RL 环境任务数，不是前述 SFT 语料条数。

领域任务族约计数量Verifier
Code软件工程3k可执行测试
Cyber漏洞复现1k规则检查
General知识工作1kRubric judging
Visual网站开发2k视觉评分
GRPO 机制简化说明

同一任务采样一组轨迹，环境给出奖励 rᵢ；用组内相对奖励构造优势，再通过策略梯度增加相对较好轨迹的概率。常见标准化形式如下，实际实现可能不同：

Aᵢ = (rᵢ − mean(r)) / (std(r) + ε)

若一组奖励完全一样，该形式的优势为零，任务奖励便不能提供组内差异信号；这不表示包含其他损失项的总梯度必然为零。SFT 的作用之一是让学生更可能探索到有效行为，但不能保证每组都会有差异。

我们需观测：组完整率、有效奖励方差组比例、任务成功率、工具错误、截断、每次成功 token/时间，以及按领域的遗忘。全错优先查任务难度、接口与冷启动；全对优先查任务是否过易。动态采样需同时报告额外采样成本与分布变化。

报告 §7 没有给出足以独立重建该 9B 全部 GRPO 配置的 batch、组大小、学习率、KL/clip、训练步数等完整信息。不能用常见默认值冒充论文值。

补充 / 方法选择与数据开放

SFT 会比 OPD 更好吗？为什么 9B 先用 SFT？

没有同条件对照，不能判断普遍优劣。论文 §7 说明目标是提供较强的任务求解基础，支持后续 RL 探索；没有提供该9B同数据、同预算SFT vs OPD消融，也没有明确说明“排除OPD”的原因。

谁产生学习轨迹通常是离线教师示范学生生成，教师在学生前缀上评分
更直接解决什么展示学生尚不会探索的成功路线、工具格式与交付行为在学生真实访问的状态上提供监督，减少示范分布与运行分布的偏差
主要风险模仿冗余、数据污染、遇到自身错误时缺少恢复示范学生探索范围狭窄、教师在偏离历史上不可靠、评分坐标不一致
资源形态教师生成成本可提前支付，数据可复用；不表示总成本必然更低训练期间持续rollout与教师评分，依赖在线吞吐及接口

合理解释，非作者明确因果结论 SFT 适合将强教师的完整任务经验交给小模型，为RL提供探索起点；跨族文本示范也不要求词表逐token对应。但不能因此断言OPD不适用。旗舰MiMo在§5.6明确采用MOPD2，包含全学生rollout及teacher/SFT前缀条件OPD，说明两者可分工组合。
