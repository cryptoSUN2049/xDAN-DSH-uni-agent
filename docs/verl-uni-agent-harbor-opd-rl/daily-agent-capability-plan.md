# 日常工作与Agent能力：9B目标、教师画像与双线推进

更新2026-09-24。用户明确目标：接近Opus4.6的日常工作/Agent能力。状态：现有结果审计与执行设计完成；新的Agent基线、1K有效性训练和mid-training尚未运行。

## 1. 目标合同

比较“固定Harness下模型能力”和“可部署Agent系统能力”两条轨道。前者固定工具、上下文管理、环境、任务、采样与预算，比较9B原版/27B教师/OPD模型；后者允许系统改进，但将模型与Harness变化独立版本化，避免把工具优化归因权重。Opus4.6是参考系统/模型，必须记录准确API版本、thinking/effort及工具支持，不将Qwen卡中的Opus4.6 Max数字当我们的实测。

主目标：真实任务完成与交付物质量；护栏：错误操作、未完成却宣称完成、人工介入、约束遗漏、成本/延迟。数学与通用知识作为保留能力护栏，不替代日常工作评测。目标是逐类达到可接受差距，不预先宣称9B可全面等价Opus。

定义“接近”必须在实验前冻结各任务族允许的质量差、失败/人工介入上限、token/时间/费用预算。先测基线方差和实际成本，再定可检验的非劣效界限及样本量；不采用单一平均榜单百分比。

## 4. 日常工作能力画像（新评测设计）

第一批约100个任务规格用于开发与可执行性审计，不作为封存测试或正式统计充分的保证。优先用户工作相关任务；与训练池按repo、文档集合、模板/任务族隔离。

| 任务族 | 候选规格数 | 必须检查的交付物 | 主要诊断 |
|---|---:|---|---|
| 软件维护 | 25 | patch、测试、回归与说明 | 阅读定位、接口契约、验证与最小修改 |
| 文件/表格/报告 | 25 | 可打开的文件、计算、引用与格式 | 数据一致性、跨文件操作、交付完整性 |
| 资料研究与综合 | 20 | 可追溯来源、事实核验、结构化结论 | 检索、证据选择、引用及不确定性 |
| 工具/多步骤状态操作 | 15 | 操作后状态、工具日志、权限边界 | 参数、规划、观察反馈、失败恢复 |
| 中文沟通与工作规划 | 15 | 满足约束的内容、可执行计划 | 需求理解、约束保持、澄清与交接 |

先采用固定离线文件/受控工具以稳定判分；实时网络能力单列，不让搜索结果变化污染配对。GUI/视觉办公属于目标扩展面，但现有文本OPD未覆盖，须另行视觉/工具验收。

每条任务同时记录：完成/未完成、实际artifact检查、质量rubric、约束违规、工具成功、错误恢复、人工介入、token/turn/时间、infra状态。不能只判回答是否说“完成”。评审顺序盲化，模型身份隐藏；确定性检查优先，开放质量由校准rubric与人工抽检支持。

每对学生/教师记录四象限：两者成功、仅教师成功、仅学生成功、两者失败。教师优势先按完整目标分布评估；只挑教师赢题训练属于明确课程策略，不能用同一筛选集报告教师整体优势。独立评测保持原分布。

预算分两轨：A同工具/同上下文管理/共同token与时间cap；B各模型推荐设置的质量—成本曲线。不同tokenizer同时报告实际费用、耗时与artifact质量。预算扫描用于开发集，不接触sealed。

## 5. 双线推进与停止条件

### A线：OPD有效性验证（主执行线）

1. 先修数据/评分合同，冻结原生文本基线与Agent迁移诊断集；旧30题只回归。
2. 验证teacher在目标任务中的优势，同时在学生真实失败历史上检查teacher监督可靠性。独立解题更强不自动等于off-policy历史评分可靠。
3. 统一EOS/停止配置，thinking-off沿用已验收路径；新增thinking/长上下文/工具模式分别验收，不混进同一个干预。
4. 依既有1K计划准备合格训练/monitor/dev/sealed。原五域配比是通用文本监督pilot，不应被包装成Agent训练配方；能力画像之后可另立版本调整，不默默覆盖原设计。
5. 观测/控制门通过后，先有硬cap的2–4步smoke，再最多一遍受控训练；全checkpoint独立dev，base/best/final sealed。
6. 输出文本收益与Agent迁移两项结果：没有Agent增益时，明确实验与目标的差距，不靠扩大文本训练承诺补上。

无可靠teacher优势、grader不可信或数值/预算硬门失败时，暂停放行，回到数据/配置诊断，不盲目增大训练量。

### B线：mid-training数据规划（并行准备线）

按能力缺口分成四类资产：repo级代码及结构、文档/表格与证据关系、长程任务执行轨迹、通用中英文保留语料。任务示范可进入SFT，长程结构语料是否用于mid-training取决于序列/目标token合同；不把所有对话示范换个名称就当mid-training。

准备DataRelease草案：用途、来源revision/许可、内容hash、语言/domain、上下文长度、loss token、轨迹分支、去重簇、验证依据、成本、评测隔离。配比由能力画像驱动，未测前不固定大规模token目标，也不承诺两卡全参数mid-training成本。

同一已核验9B起点为主对照；base与已有SFT模型的比较另立实验，避免同时换起点、数据与算法。mid-training启动前需测防遗忘、packing/label/mask、优化器恢复、数据流重建和算力预算。

## 6. 执行接口与拟改范围

复用training-pilot-1k-plan.md既有data_pilot/与control/设计；新增任务资产与评分规格置于版本化数据目录。为代码题面补prompt/reference/test一致性检查；开放任务输出GraderRelease。报告新增四象限、失败类型、artifact质量及行为预算。

最小接口：TaskRelease→reset/run/collect_artifacts；grade→status/score/rubric/evidence；pair→task_id/model_revision/protocol_revision/outcome/cost。实际集成前按项目Human Gate呈现具体改动和测试，不把本规划当已部署。

验收测试：已知正确/错误/空交付物、超时回收、跨题状态污染、工具输出mask、模型身份盲化、reference隔离、group split泄漏、暂停与预算、独立checkpoint重载。
