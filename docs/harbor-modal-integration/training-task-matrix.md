# 有价值任务 × 训练方法 × 工程验收

状态日期：2026-09-08。目标模型Qwen3-4B，当前固定DSH0.1.3a2、Uni-Agent89733ec、VERLfefb080；每次执行另记录集成commit和完整manifest。性能优化（全异步、Modal、扩容）延后。

## 六个递进任务

| 任务 | 具体工作与价值 | 独立评分 | 当前基础 |
|---|---|---|---|
| T1 实时能力查询 | 根据当前DSH运行时查询可用Tool能力，不能凭记忆编造接口；为正确调度打基础 | 实际listing→查询其中合法接口→成功结果；后续增强最终报告与实际清单逐项一致 | 单题baseline已失败：误查Service大目录导致容量耗尽；现verifier不全面检查最终文字 |
| T2 注册工具并完成业务处理 | 在DSH注册一个参数化JSON记录筛选工具，按公开筛选条件处理输入，再停止/移除工具；与只输出字符串不同，必须走注册与真实调用 | 注册身份、至少两个不同输入与独立Python oracle逐项一致、停止后工具撤销、最终清理；独立隐藏输入在代码冻结后执行 | 可复用生命周期API；新业务fixture与严格verifier待实现 |
| T3 依赖故障恢复 | 获得有故障的工具Plugin，读取运行时诊断，在同一Plugin下修复依赖并恢复真实查询功能，然后清理 | 按序绑定Plugin/Package/Run，waiting→修复→running，多输入功能检查，stop/undefine及终态清单；不能靠passed文本 | 原v3素材存在，但旧verifier不严格；新设计已落盘，未实现 |
| T4 长流程事实保真 | 调查多份工单/配置，提取目标、权限、关键事实和未完成事项，经历明确上下文切换后完成有约束修复 | 最终功能测试、关键事实准确率、权限约束、未完成事项遗漏；读取/摘要/恢复动作留证据；压缩token数量不作为成功指标 | 任务、上下文操作与因果对照需新合同；不是现有trim数据 |
| T5 A写入→B检索 | A会话记录客户配置/约束/排错事实，B全新会话通过授权检索解决后续问题；禁止直接注入A完整对话 | 两个独立session身份、记忆写入和检索证据、事实一致与最终任务结果；比较无记忆对照；不同case隔离 | ContextPilot参考素材存在；所需扩展未全部进入当前runtime，尚未集成 |
| T6 有边界的Harness改进 | 在允许范围内提出工具配置/上下文策略候选，执行对照评估，选择有效候选或回滚 | 独立baseline/候选与留出任务比较，同时满足成本、事实保真、权限和清理约束；验证器不可被候选修改 | 后续RSI阶段设计；不是任意自改代码或自动提高模型权重 |

T2筛选条件与输入schema由任务明确提供，期望结果由独立oracle计算。模型必须提交可复用的DSH工具并真正调用，不接受只对当前样本硬编码答案。T3采用公开允许修改的依赖槽，完整功能主体冻结；第一批是受控DSH技能任务，不宣称通用生产故障修复。

## 首批顺序与学习方法

1. T1 baseline先完成，作为新版runtime调用协议与能力薄弱点诊断，不重复满分题RL。
2. T2完成oracle/负例/verifier与未训练模型baseline后，先做一个很小训练批次；若起点全失败，先提供高质量SFT示范，再进入可验证奖励RL。
3. T3补强严格评分后加入，训练真实诊断与恢复；与T2分别记录效果，不混合后看不清增益。
4. T4/T5单独接入上下文/记忆合同，再复用已跑通训练部署和审计。
5. T6在稳定任务与留出评估之上推进受控Harness演化。OPD/教师模型指导可作为后续训练方法轴，不是前置必需服务。

训练方法、任务场景、Harness版本和参数更新方式分别记录。SFT不是RL；LoRA只是更新参数范围；on-policy必须绑定实际采样策略版本。多轮任务、跨会话记忆、采样/更新和候选演化四种循环使用独立身份。

## 本次G1如何验收

最短有价值闭环以T2为主、T3作为下一增量，T1辅助诊断。先DSH原生任务真实执行与评分，再用Harbor+Docker承载一个对应业务任务；同一结果标准不意味着复用旧receipt。Harbor版本和独立verifier环境必须各自冻结，不通过复制旧运行证据补门。

每个运行依次过门：

1. **版本/数据**：源码commit、SDK/runtime/wheel、模型与tokenizer、task/verifier/镜像摘要及运行预算固定。
2. **任务真实执行**：DSH拥有执行循环，工具动作与结果可追踪；任务oracle通过、no-op/篡改/错实例等负例被拒绝。
3. **可训练轨迹**：Gateway真实token/logprob、完整组、fresh reward、policy/session/task身份对齐，基础设施错误不伪装普通0分。
4. **优化器更新**：合格组与训练batch匹配，有限梯度、优化器步数推进，LoRA张量数值变化、base冻结；checkpoint文件存在不够。
5. **独立reload**：新进程从明确checkpoint恢复，独立运行身份，重新执行并核验输出。
6. **留出评估**：不同输入/task实例，相同预算做训练前后比较；报告成功率、功能正确率、调用错误/清理失败，不要求几步必然显著提升。
7. **可复建**：从GitHub固定commit安装部署并复验，运行配置与证据可追溯。

G1工程通过不等于4B已经具备全面记忆/RSI或Terminal-Bench提升。效果阶段另需足够样本、多次运行与相同预算对照。
