目标与证据级别

目标是让4B在DSH中自主诊断、检索经验、提出有界改进、验证并决定是否采用，在后续任务复用。Harness RL是核心学习目标；RSI不仅指外部强模型替学生改代码。

  • 任务内修正：修好当前产物，不代表下次更强。
  • 可持续改进：新Harness/记忆策略在新进程和独立任务中有效。
  • 递归增强：诊断、候选选择或搜索策略本身提高，在新任务分布上以同预算产生更多有效改进。

前两层为近期交付，第三层为单独研究验收。所有阶段目前为规划，不能写成已完成RSI。

从指定研读资料吸收什么

  • Meta-Harness：检索源码、原始trace、分数与失败记录。摘要只做索引；其部分benchmark内搜索成绩不能当独立泛化证据。
  • DGM：区分归档资格、搜索父代资格和部署资格。负收益候选可供诊断或探索，不自动进入运行环境。
  • Self-Harness：一次窄改动、明确失败机制、重测回归。反复参与选择的held-out实质是验证集，另保留最终封存集。
  • SIA：允许模型与Harness交替更新，但补独立weight-only与同预算对照，不能把联合提高自动称为协同。
  • Updating / Benefit：会写技能不代表会发现、调用并持续遵守。加入无技能、自然发现、显式提供三组诊断；显式提示组不作为自主能力成绩。

以上是对本地研读报告的设计采纳；本轮没有重新核读全部原论文或复现其实验，不承诺论文收益迁移到4B。

系统位置与动作合同

任务 / 失败证据 → 4B诊断与提案 → 版本化候选档案
↓
独立环境测试 → 验证集选择 → 冻结候选 → 最终评估
↓
外部Controller执行晋升 / 回滚 → 新进程与新任务复用
↓
合法学生轨迹 → Uni-Agent准入 → SFT / OPD适配 / VERL RL

DSH负责工具、状态和候选执行；Uni-Agent复用Gateway与训练能力；Harbor负责任务环境与验收；ContextPilot提供上下文/跨会话课程与数据合同；Modal可选。

逻辑动作（待映射到实际工具，不是现成API）：inspect_evidence、retrieve_attempts、propose_candidate、run_candidate_tests、request_promotion、request_rollback。学生可以提出采用决定；外部Controller按冻结规则执行，不由候选修改自己的准入规则。

最初只开放版本化技能、记忆/上下文策略配置、candidate-owned插件或composition。评价器、最终评估数据、凭据、权限边界和日志不属于候选编辑范围。后续研究改进搜索策略，也不能开放最终裁判。

分阶段交付：R0—R5

  1. R0 可执行基础：复建DSH并验证学生真实轨迹；检查候选进程隔离和生命周期。静态4B、相同工具的大模型作基线。现有动态插件不等于跨进程持久部署。
  2. R1 先会利用改进：提供一个经验证有用的技能/记忆资产，测自然发现、调用、遵循、不适用时拒用和后续任务收益。不会使用时先补针对性SFT与策略层Harness RL。
  3. R2 自主小改进：从一种重复失败开始，4B生成一个窄候选；记录所有尝试成本，独立测试，重新启动后复用，并演示新版本→旧版本回滚。先冻结模型，验证Harness-only净收益。
  4. R3 学会改进过程：收集学生提案、测试解释、拒绝与采用轨迹；奖励依据独立开发/验证任务结果与成本。先任务级RL，再研究延迟信用；OPD须先解决adapter的teacher_client阻断。
  5. R4 多轮积累：候选档案与记忆跨Session复用，包含失败经验检索；合并改动后重测组合版本。比较无档案、摘要索引、可检索原始证据，同预算验证多轮收益与回归。
  6. R5 递归改进研究：固定初始任务能力与总搜索预算，对比冻结改进策略和学到的诊断/父代选择/候选策略，在新family上测单位成本有效晋升数、达到目标的成本和最终质量。至少多轮、多任务族证据；一条向上曲线不算证明。

R1属于近期核心能力，不必等所有终端成绩提升后才研究。R2可在真实运行基础就绪后作为冻结模型的独立实验；不是重建整套训练器。具体规模和晋升阈值在基线后预注册，不在观察结果后挑选。

奖励、训练信号与数据隔离

优先任务质量、合法性和回归约束，再考虑成本。第一版只把通过冻结准入规则的结果用于训练，记录各项指标，不先拍一个万能加权分数。插件生成数、写入lesson数、工具调用数都不能直接作为能力奖励。

  • 成功示范与真实失败纠错用于SFT；不能把失败轨迹不加区分地当正例。
  • 在线RL记录生成token、mask、概率、policy版本、父候选、环境与fresh结果。文件改动只是动作产物，不能伪造为模型生成token。
  • 跨Session记忆奖励由后续任务结果回传；需完整chain lineage与冻结转交产物，不能把原始答案暗中传给新会话。
  • search/train、validation、sealed final按任务族/环境变体/Session chain划分；最终评估反馈不返回提案者或训练。若反馈被用于下一轮选择，该集应改列开发资料并另设最终测试。
  • 基础设施失败显式单列；不能默默从总体结果中删掉，不能伪装成干净的任务失败训练样本。

证据合同与版本状态

拟定CandidateRecord：candidate_id、parent_id、model/DSH/tool revisions、source/artifact hashes、failure references、hypothesis、allowed changes、test/split/verifier identities、costs、decision、active version。所有字段的实现与迁移在R2接口设计中冻结。

状态：proposed → tested → archived；parent_eligible 与 deploy_eligible 分开记录。晋升记录active版本和前一版本；失败、拒绝、取消都留记录。回滚必须在新进程复验旧行为，不能只修改一个版本指针。

指定资料指出：旧DSH动态定义只在当前进程存在，受限调用不等于恶意代码隔离，update失败不会自动重启旧版本。本轮未重新复核最新DSH源码，R0必须核验固定revision的真实行为。

评估矩阵与停止条件

固定共同候选H1，分别评估M0H0、M0H1、M1H0、M1H1。Harness效应=J01−J00；模型效应=J10−J00；交互=J11−J10−J01+J00。结果含不确定性，联合最高不自动代表正交互。训练与搜索成本另外做匹配预算对照。

成绩分三组：DSH专长、记忆/上下文、固定Terminal-Bench v4.0.0。开发任务按真实短板选；不能用全套封存benchmark反复驱动RSI。小型CPU子集仅证明集成。

停止并记录：验收器漂移、跨split污染、不可恢复状态、候选越界、预算耗尽或回归超过预注册阈值。没有可靠增益时保留负结果，不为“证明RSI”继续放大搜索。论文建议的20 paired tasks只是历史下限，不保证统计功效。

实施归属与下一批设计

  • Uni-Agent：版本化候选/运行证据接线、训练数据准入、统一实验与评估入口；先审计已有DSH ops，避免重复。
  • DSH-Exp：缺失的候选持久化、加载/撤销和上下文工具语义在DSH本体实现。
  • ContextPilot：复用源投影、课程和数据编译产物；参考分支算法不得替换本项目固定VERL。
  • 下一批规格：先一个“有用技能的发现与遵循”任务，以及一个“Session A保存→Session B检索”的任务；分别写实际工具映射、文件清单、CPU拒绝测试、真实执行与评估合同。

这份RSI路线不是已可运行API。实施前完成逐批详细设计；既有H0授权继续有效，新算法/接口按项目设计流程具体化。付费运行范围不因文献研读扩大。
