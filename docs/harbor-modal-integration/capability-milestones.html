排期原则

工程贯通 → DSH策略内化 → 记忆与受控演化 → 联合验证 → 性能规模。按验收门推进，工作日为工程估计，不是效果承诺；DSH发布物恢复、容器权限、数据质量和单卡资源均可能改变工期。沿用M1/M2工程里程碑，以下C1—C5为能力里程碑，不替换既有S/P/R编号。

依赖与建议工期

M1/M2（约3—7工作日，环境阻塞另计）：固定部署版本，恢复历史闭环，接通Harbor单任务，真实update/reload和前后eval。

C1（约5—10工作日）：固定Harness训练DSH调度；C2任务与观测合同可同时设计。

C2（约5—10工作日）：接入记忆与多context，A会话写入→B新会话检索。C3a可并行做冻结模型的Harness候选实验，但单GPU训练串行排队。

C3a（约3—5工作日）：冻结模型验证一个窄范围候选的跨任务复用与回滚。

C3b（约5—10工作日，依赖C1与候选数据）：训练提出/选择/验证/拒绝改进的行为；涉及记忆策略时还依赖C2。

C4（约3—5工作日）：冻结候选与checkpoint后做权重×Harness四组归因和独立长任务评估。

C5（约3—7工作日起）：根据瓶颈调优；多GPU全异步和Modal按实测需求另估。首个有效能力结果争取在M1/M2之后1—2周出现；完整体系不承诺固定日期。

C1：DSH Harness策略内化

固定工具接口与Harness实现，模型学习何时发现/调用技能、分解与调度、检查结果、恢复错误和停止。首批2—3类场景：多文件修复并运行测试；依赖任务的工具调度；注入可恢复故障后的完成。先做frozen baseline、检索/few-shot基线；缺少合法动作示范时补高质量SFT，已有基本能力则优先结果奖励RL。OPD作为后续对照，不作为首轮前置。

验收：相同工具/Harness/预算下，独立reload后的4B在未见实例完成率提高；同时报告无效调用、恢复率、成本与失败类型。减少提示示范后复测，以区分权重内化与提示帮助；不要求把外部执行代码装进模型参数。

C2：记忆与多context

复用Uni-Agent MemAgent的4B训练经验、数据/分段思想和轨迹支持；当前recipe默认4张trainer+4张rollout GPU，单卡需改配，不能视为直接可运行。DSH保持唯一任务执行循环，ContextPilot贡献动作前观测、记忆写入/检索语义与事实保真验证。

任务先做A读材料并写入持久记忆，B用新会话完成依赖这些事实的新请求；B不隐式继承A聊天记录。记录允许共享的文件和索引、冲突事实/过期事实及干扰记忆。终局奖励可关联A写入，但须显式实现跨会话信用分配，不能假设训练框架自动回传。

对照：不带记忆、当前记忆策略、训练后策略；固定模型做记忆机制对照，再固定机制比较模型。主要指标为B任务成功、事实准确、引用来源和恢复能力；token成本为次要指标，压缩更多不算独立成功。

C3：从静态到受控动态Harness

C3a固定模型，只允许改一个版本化技能/插件/工作流；保留原始失败trace→提出有界候选→独立验证→新进程在不同任务复用→可回滚。候选档案、可作父代、允许采用分别记录。

C3b训练4B何时需要改进、如何利用失败证据、发现/使用已有技能、提出候选、验证和拒绝坏候选。比较无候选、自然发现候选、显式提供候选，避免把强制注入当作自主发现。若由teacher提案，标记外部贡献，再单独检验4B提案能力。

验证器、权限、预算、封存测试集与采用控制不由候选修改。动态插件生成不等于持续RSI；只有新任务上同预算的改进效率提高，才进一步讨论改进机制本身的递归增强。

C4：归因与效果门

冻结W0/W1权重与H0/H1 Harness，比较W0H0、W1H0、W0H1、W1H1；计入teacher/controller、候选失败、搜索和验证成本。分离搜索训练集、候选选择验证集与最终封存测试集。

工程阶段少量任务只验证流程；效果阶段预先冻结主要指标和最小有意义增益，再用pilot估算样本量与方差。至少20个paired任务可作探索起点，不保证统计功效；报告任务族相关性、置信区间和重复种子，禁止看到结果后挑指标。针对DSH更擅长的主张，大模型对照必须使用相同工具、环境和预算。

C5：长流程性能与规模

Harbor/Docker的单任务可执行与评分在M2完成；长任务成功与恢复在C1/C2/C4验收。此阶段优化系统吞吐、p95耗时、每成功任务成本、GPU利用率、失败率和策略滞后。先profile和减少重复启动/无效上下文，再扩大并发；质量与版本证据不退化才采用全异步或Modal。

Docker可在本地或云端运行，Modal是可选托管环境；二者不是长任务能力的学习目标。当前服务器只读未发现Docker CLI/socket，Harbor环境方案须验证，不能默认云Pod里能直接运行Docker。

四类循环与身份合同（待实现字段）

任务内长循环：task_id / episode_id / trial_id / session_id / model_revision / harness_digest。

跨会话记忆链：memory_chain_id，关联A/B session、memory_snapshot_digest、可见性范围、事实来源与延迟奖励；独立evaluation链不得读训练残留。

采样/更新训练循环：run_id / policy_version / rollout_group_id / optimizer_step / checkpoint_digest，保留token、mask与verifier receipt。

候选演化循环：search_run_id / candidate_id / parent_candidate_id / source_digest / proposer_revision / selection_decision / rollback_target。

以上是接口设计，不宣称均已在代码实现。ContextPilot树分支partial rollout保留branch/parent/state身份；全异步partial rollout保留chunk/resume/policy-version身份。两者将来组合需明确映射、奖励归属及陈旧策略处理，不能共用一个含糊的partial标记。
