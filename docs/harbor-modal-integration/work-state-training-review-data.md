# 工作状态 RL：首批任务、数据与奖励独立审查

2026-09-09。只读审查完整 `dsh-memory-context-skills-plan.md` 与当前 DSH 文件动作接线；本文是实施合同建议，不是已生成数据、已冻结奖励或 GPU 验收。保留现有 pin、DSH 唯一 loop、Uni-Agent/VERL；不修改旧 memory 诊断评分器。

## 结论与立即可执行边界

完整设计的方向合理：终局工作恢复而不是文件格式模仿，合法低质量样本不再一律挡在 A 阶段，公开种子与封存测试分离。但首批应先收敛到 **WS01／WS03／WS05／WS06 四类文件工作流**，不把模型可见 shell、compact 或搜索工具当既有前提。

当前 [memory_closed/policy.mjs](../../examples/dsh/memory_closed/policy.mjs):36 只允许 `str_replace_editor`；view 的路径必须在固定 readFiles，create/str_replace/insert 只能操作唯一 writeFile。`create` 的 `file_text` 是字符串；写入值发生在执行请求前，不能在同一轮先生成读请求再假定写入参数已看到其结果。[profile.py](../../examples/dsh/memory_closed/profile.py):11 禁用 bash/pwsh。当前旧配方不是多文件索引课程的直接执行器。

需要的新版本最小变化是：限定项目根内若干可写工件、已存在只读来源的权限；A/B 每 sibling 独立文件状态；index 作为 B 已知唯一入口；最终工件由控制端独立程序检查。首版不需要让模型自己执行测试命令：控制端检查最终 JSON 配置和执行计划即可证明业务结果，之后再扩真实代码修复与模型测试反馈。必须先有工具 canary 证明合法读写/更新、非法路径/链接拒绝。

**现有 policy 不能照搬的一点：** denial reason 在 :47—55 会列出所有允许源路径。若新索引任务让模型靠故意越权得到完整文件目录，就破坏了索引发现合同。新版应只提供模型当时已获准知道的入口/通用错误，不通过拒绝信息泄露隐藏目录或 controller 状态；工具可访问与路径已告知是两回事。

## 四类首批精确合同

这些文件名是任务工件约定，不是新 DSH API。每类应有不同依赖结构的实例及可评分负例，所有示例都是开发规格。

### WS01：中断后继续一个有依赖的配置迁移

- 初始项目是小型服务配置＋迁移 ledger＋带版本的检查回执。A 获得迁移目标，读取当前配置/回执，可修改 `work/config.json`、写 `state/handoff.md`、发布 `state/index.md`；源码真值、不可重复初始化 ledger 的权威副本由 controller 保持只读。
- controller 在预先固定动作边界切换到真正新 B，输入可信目标、当前事件通知和唯一 index 入口。A 的普通对话/原始临时日志不转交；哪些项目文件持久化在生成前确定。任务目标包含后续恢复，预算/阶段信号对 A 可见，不要求猜未来。
- B 交付当前版本 `work/config.json` 与声明式 `work/remaining-steps.json`。controller 在干净 fixture 上执行该计划，核依赖顺序、最终配置与 ledger；“初始化已完成”若误判会导致重复初始化，执行检查失败。模型写 done 本身不改变权威 ledger。
- 成功条件：新配置满足独立用例、已完成步骤不重复、遗漏步骤补齐、done 声明对应同版本真实回执。Handoff 不是必需文件名；任何获准状态组织能恢复都允许。
- 主要反例：把旧版本通过当新版本通过；遗漏未完成依赖；复制完整日志超预算；A 合法保存有缺陷时仍冻结原样，让 B 有机会纠正或真实失败。
- 可学习变化：改变依赖 DAG、已完成位置、升级范围、事件发生位置；不是只替换 region 或路径名。

### WS03：从索引定位多模块证据并完成配置选择

- A 调查三个以上模块，每个模块有真实配置、测试结果、版本约束；只有部分证据与最后交付相关。A 可写有限 index 和各模块摘要；大量原件保持按合同可寻址，不能全量装入 B 的请求预算。
- B 只知道顶层 index、明确业务问题与获准根。需要从索引找到版本正确的模块证据，交付满足兼容约束的组件组合/路由配置；controller 运行兼容矩阵和查询用例，而非看“引用了几个路径”。
- 不告诉 B 正确文件路径；允许索引替代组织，不按固定标题给分。重复读全部文件计入冻结的成本预算，但不能仅通过禁止合理检索人为制造失败。
- 无持久化对照确认材料确实不能凭基座猜中；固定规则索引对照判断模型组织是否优于简单模板。A 保存的数据不可包含尚未公布的后续题答案或 oracle 判定。
- 主要反例：有索引但目标不存在；路径指向错误项目；同名模块错误版本；信息正确但检索成本高。合法坏索引属于低质量可训练样本，不自动当越权。
- 可学习变化：模块依赖关系、证据分散位置、查询目标组合、索引过期模式；路径随机化只作去记忆化，不能算独立任务结构。

### WS05：冲突事实、适用范围与真实目标变更

- A 已有旧 handoff/配置/通过回执，随后获得可信发布的用户变更；同时存在时间更晚但仅适用于另一 worktree 的材料。
- A 可更新索引/状态并保留来源。B 只有可信当前目标、index 与合同内原件，必须交付当前项目配置及待做计划；控制端按 scope、发布身份和目标版本决定期望行为，不能以文件 mtime 充当真值。
- 成功条件：最终配置和执行结果符合新目标；未受影响的已完成步骤不重做；受影响项重新验证；旧成功证据不能为新状态背书。陈旧事实若已标记失效且不被采用，不因“文件里存在错误字符串”扣分。
- 主要反例：最新文件优先但范围错；A 生造来源；B 盲信 done；覆盖失败原件。普通错误记忆低分；篡改控制端证据/跨 sibling 访问硬拒。
- 可学习变化：目标变更涉及不同字段间约束、版本分支与作用域、来源权威关系；不要只有一个固定 latest/current 字段供照抄。

### WS06：该保存时保存，不该保存时克制

- 由共同任务族提供两种可辨识情境：单会话小配置修正（无后继依赖）与有明确恢复需求的阶段任务。短任务不要求写 memory、handoff 或 index；交付目标直接可验证。
- 评分以正确完成为主；只有同样成功时，额外持久化、无用读取和大篇摘要才增加成本。不能给“不写”固定高分，或将同样完成但选择轻量交接的合理策略判失败。
- 无关噪声来自普通非敏感 fixture；不把真实秘密塞入样本来测试泄漏。该类仍核写入只能发生在获准根；控制端记录是否持久化但不要求模型自报。
- 短任务原始 prompt 的任务范围必须足够明确，不通过事后增加未知未来任务惩罚“不保存”。与需保存的对照使用相近表面形式，依赖真实情境判断。
- 可学习变化：可重查成本、后继依赖、信息时效、终局工件复杂度；不能所有短题一句提示“不要保存”就测作自主选择。

## 可学习性门：在扩大样本前必须回答

1. **行为会改变结果吗？** oracle 工件可成功；缺关键状态/坏索引/错误作用域的版本真实失败或增加恢复成本；无持久化基线对必要记忆题显著受限。若 B 凭公开 prompt 即可还原隐藏状态，重做信息边界，不能继续靠格式约束造难度。
2. **模型能探索吗？** 原旧 prompt 直接规定先读并复制 JSON（[memory_tasks.py](../../examples/dsh/capabilities/memory_tasks.py):45），只适合诊断。新版应给目标、权限与预算信号，开放合理保存组织/检索顺序；不把每步答案脚本化。模型无需知道内部 call ID，控制端用实际调用配对。
3. **A 的错误有没有学习通路？** 安全且可解析/可冻结但低质量工件允许 B 尝试；缺 index 时 B 可依合同降级搜索、报告不足或失败。越权、证据伪造、基础设施错误隔离。不能把质量差/缺文件全部称 infra，也不能放宽权限换取样本量。
4. **奖励可归因且不投机吗？** 首版以终局通过/失败二值为最简默认，独立记录 progress、成本与事实错误。若需要部分奖励，只有预先可执行子测试作为 progress；候选 0.9—1/0—0.2 档位需基线后冻结，成本计所有阶段。不要直接把宽泛的“交接看起来完整”交给模型评分。
5. **GRPO 组有没有可信差异？** 同题同事件种子下 n4 独立采样，终局差异来自策略而非 controller 不同随机干扰。报告全同分比例、合法失败比例、有效组与梯度；真实异质策略全零仍需改下一版任务，不人工改分。

## 数据与实施顺序

先做四个模板各一个确定性开发实例＋对应业务错误/越权反例，证明真实工具可解、独立 verifier 正确；这不是四题足够做能力训练的承诺。再为每类加入至少一种结构变化做开发诊断，按失败分布扩充训练实例。封存集在模板/项目结构层划分，不使用这些公开设计样例；n4 是四次尝试，不算四个独立任务。

优先复用原 Task/StageSpec/Gateway/TQ；新工作状态合同允许多个声明式工件，保留逐阶段原 reward 和链级终态 credit。不扩通用 sandbox，不在当前 GPU run 改旧 policy。A 产物由控制端原样冻结，B 真正新 session，所有入口/读写/版本/终局测试回执可复核后，才进入训练消费。任务完成、原生 RL 数值更新、独立 reload、固定规则对照的能力提升分别验收。
