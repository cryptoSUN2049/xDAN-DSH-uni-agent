# 记忆与上下文 RL：学习证据、论文依据与下一实验

日期：2026-09-10。本文为研究与实验设计，不改变已完成 r4 的任务、奖励、准入或训练结论。P1→P2→P3 目标保持；新实验合同实施前需完成设计评审。

## 先定义“有效”

1. 工程闭环：真实策略采样、完整组实际消费、正确 token/mask/logprob 与版本绑定、奖励、更新步骤、checkpoint 和独立 reload。
2. 优化发生：来自任务的有限非零优势与梯度，实际参数变化与非零优化器状态相互印证。仅 optimizer 计数、文件 hash 改变或历史动量推动参数变化不够。
3. 任务学会：相同模型初始点、harness、预算、任务拆分下，未参与训练的数据上表现提高；报告多次采样的不确定性。
4. 记忆有贡献：在确实需要记忆的任务上，配对移除/替换记忆会损害表现；不需要记忆的负对照不应被迫写文件。
5. 泛化：新模板、未见场景、不同中断位置、更多干扰和更长跨度仍能完成任务。更多随机种子不等于更多结构。

当前证据：ws-short-train-r1 第2/4步有真实任务梯度及非零LoRA B，但尚无同条件能力收益对照。core-train-r4 16步实际消费通过，优势/梯度全零，最终LoRA B全零，未通过有效更新门。不要用旧短课成功代替新课程学习。

## 原论文与可迁移点

以下阅读固定版本/原作者页面；不声称穷尽2026全部论文，不将论文结果当成本项目复现。

| 工作 | 真正优化什么 | 对本项目的启发与边界 |
|---|---|---|
| [MemAgent，2025-07](https://arxiv.org/html/2507.02259v1) | 多个独立context生成记忆，最终问答结果用于多conversation RL | 借鉴跨段信用分配；固定分块长文问答不等于主动文件管理或DSH任务执行。已有Uni-Agent recipe可参考，不能再包第二套DSH外循环。 |
| [MEM1，2025-06](https://arxiv.org/html/2506.15841v1) | 将记忆整理与推理一起进行端到端RL，按问答/环境结果反馈 | 保留支持后续行动的状态；原文附录D.2指出格式奖励可加速收敛却降低最终成绩，不能把格式合规当能力。 |
| [Memory-R1，2025-08](https://arxiv.org/html/2508.19828v1) | Memory Manager学习ADD/UPDATE/DELETE/NOOP，Answer Agent学习选择利用记忆，两者接受结果驱动RL | 分离写入质量与使用质量，包含不写入/不修改的正确决策；对话记忆问答证据不能直接外推复杂工程执行。 |
| [Context-Folding / FoldGRPO，2025-10](https://arxiv.org/abs/2510.11967) | 学习分支子任务与折叠返回，结合过程奖励 | 与真实context生命周期相关；它改变动作/训练合同，不是仅调整窗口长度。 |
| [FoldAct，2025-12](https://arxiv.org/html/2512.22733v1) | 区分摘要与动作的训练信号，并处理折叠后的上下文分布变化 | 提醒我们保持各段真实条件前缀、策略版本和loss归属；不直接搬新loss到固定paired VERL。 |
| [MemexRL，2026-03](https://arxiv.org/html/2603.04257v1) | 学习归档、摘要、索引、解引用；分段训练共享最终回报，并约束上下文与冗余 | 最贴近offload→index→按需恢复目标。奖励包含任务结果及上下文/冗余/格式惩罚；不能照搬系数，更不能让节省成本压倒任务成功。 |
| [MemRL，2026-01](https://arxiv.org/html/2601.03192v1) | 冻结LLM，依据反馈更新记忆效用/Q值以改进检索 | 是外部记忆策略学习，不证明4B模型参数内化；可作后续harness侧对照。 |
| [ACE，2025-10](https://arxiv.org/html/2510.04618v1) | 更新外部上下文/经验playbook | 可借鉴经验增量维护，但不能称模型权重RL；与参数训练收益要分开测。 |

MemAgent原文消融比较同模型有无记忆机制、有无RL，并测长度外推和OOD任务；这是值得复用的实验逻辑。MEM1报告的训练早期格式学习、后续任务策略变化说明要同时看合法动作率、搜索/读取行为与最终成绩；不能规定若干步就必然学会，也不能无限等待全零GRPO自发变化。

## 下一轮先做可辨识诊断，而非直接扩大训练

保持模型、DSH/runtime、工具接口、预算与评分器固定，先在公开开发数据做分层诊断。每个条件使用相同题目和采样设置，诊断产生的数据不混进封存测试。

- D0 工具基本功：必要事实直接给定，能否用真实工具完成配置/计划。若这里失败，先定位工具协议或执行任务，不能归因记忆。
- D1 读取能力：控制端提供正确但不泄露最终产物的事实文件，学生必须检索后完成任务。此条件是明确标记的诊断，不冒充学生自主写入或训练样本。
- D2 写入能力：学生A写记忆，用固定诊断读取器检查事实可恢复性；区分遗漏、事实错误、索引断链。读取器成绩不能当学生B成绩。
- D3 联合链：真实学生A→冻结文件→新学生B。奖励以最终任务结果为主，原始全过程保留，验证早期写入token实际收到信用。
- D4 对照：移除记忆、无关记忆、过期事实与无需记忆任务。仅对确实依赖记忆的题目解释移除差异，并确认没有其他通路泄漏事实。

当前已有B角色歧义的单变量候选，且实际prompt含工具示例；不要重复“补缺失示例”的错误诊断。先完成旧r4四族reload，随后在新源码/新run验证已实现的累计token预算，再开展上面的公开诊断。

## 从有信号到有收益

先测每类基础成功率、完整组率、同组奖励标准差、有效优势组比例、拒绝原因及单位GPU时间有效组数。二元成功率p、独立n=4时混合成功失败组概率为1-p^4-(1-p)^4；它只说明过难/过易都低效，实际采样相关时不能当预测。

选择有真实可达成功路径又有失败的训练课程，逐步增加事实数量、干扰、冲突、跨会话次数和任务跨度；保留困难题覆盖，不按最终成功偷偷筛掉失败。若没有可达成功，增加步数、学习率或异步不会创造任务信息。

阶段性任务奖励可考虑可执行子目标（配置符合事实、依赖顺序正确等），但必须预先定义、版本化、检查刷分反例并保留严格最终成功指标。文件数量、字数、读取次数、压缩率只作诊断，不直接代表收益。所有可信失败的准入变更见core-negative-trajectory-admission-review.md，不能删除assert或伪造B补全旧合同。

## 模型与harness协同如何测

固定验证器/环境，做2×2：基础模型M0+原harnessH0；训练模型M1+H0；M0+候选H1；M1+H1。前两者差异衡量固定harness下模型收益，第一与第三衡量固定模型下harness收益。协同增量可报告(S11-S01)-(S10-S00)，需要任务配对与置信区间，不能从单题推断。

每轮只变一个主要因素，候选不能修改评分器、偷看答案或放宽权限。先固定H训练M，再冻结M评估H候选；交替推进更易归因。动态harness候选演化循环与模型采样/更新循环使用独立身份，不宣称当前已经完成协同RL。

## 预期验收与停止/调整条件

- 运行期间持续核任务消费、优势/梯度、LoRA状态、熵、KL/clip统计及失败分类；不单看GPU利用率。
- 学习阶段：跨多个实际更新批次观察任务梯度，保存初始/中间/最终可比较参数；不能只凭两次checkpoint差异。
- 能力阶段：固定公开开发调试边界后封存新任务，做同条件前后评估、记忆消融与跨模板测试，报告绝对成功率、差值、不确定性、成本及回归。
- 连续完整组全同分时先诊断课程/奖励可辨识性，不能以随机奖励、提高KL或动量产生的变化冒充学习。
- 工程成功、优化发生、能力提升分别发布；原P1/P2/P3退出标准不以论文或这份设计代替实测。
