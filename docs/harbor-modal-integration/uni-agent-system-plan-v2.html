01 · v2 的位置与范围

一套可复用的工程模型训练体系，先工程贯通，再提升任务效果，最后优化性能与规模。

本页是当前worktree的系统架构规范入口；S0—S11路线图负责执行依赖与验收；handoff负责实测状态与冷启动。首页只做导航，不再维护另一份完整架构。

v1的分层架构和两条环境路径继续保留。v2新增学习方法模块、上下文/记忆能力、RSI控制面、三阶段交付与成对版本迁移。原v1不修改，见继承快照。

02 · 终局目标与三阶段

阶段要证明什么主要范围
Ⅰ 工程贯通真实任务→可信数据→参数更新→保存→独立加载可以复建恢复历史DSH链路、Harbor/Docker最小增量、评估工具；不以提分作为工程通过条件
Ⅱ 任务效果同预算未见任务表现提高4B的DSH专长、记忆/上下文、终端任务、Harness RL与受控RSI；按缺口选择SFT/OPD/RL
Ⅲ 性能与规模保持质量，减少耗时或有效样本成本全异步、并发、资源调度及可选Modal；第一阶段必要GPU使用不属于规模优化

先以4B验证，9B及其他模型通过相同合同扩展。DSH专家能力要通过真实操作与同工具大模型对照证明；不承诺4B在所有通用benchmark超过大模型。Harness RL是核心目标，Modal不是必需组件。

概念地图 / 根据用户截图补充

概念不能混排：一次实验由多个维度组成

学习目标 × 采样策略 × 任务场景 × Harness × 更新对象 × 执行环境 × 训练实现 × 调度方式。

这里的“×”表示分别选择、共同描述一个实验，不是任意组合都已经兼容。下面区分功能、数据、算法和部署，防止把换云平台误称为换训练方法。

维度回答的问题例子与边界
学习信号/目标模型依据什么反馈更新？SFT模仿示范；GKD匹配教师分布；任务RL利用奖励。GRPO/PPO是具体RL方法，OPD横跨采样与教师监督。
数据来源任务和轨迹来自哪里？人工/教师示范、学生rollout、公开可执行任务、历史日志；来源不等于训练资格。
采样与策略关系轨迹由什么版本的策略产生？on-policy使用对应当前学习策略的采样；off-policy来自其他或较旧行为策略。学生自己生成也可能因版本陈旧成为off-policy；异步需要版本与偏差处理。
教师监督/蒸馏教师提供什么、指导哪个状态？完整示范、学生访问状态上的分布/采样token概率、纠错建议。教师生成轨迹再SFT与OPD分开命名。
任务场景与长度Agent在什么问题上做多少步工作？DSH操作、terminal/repo修复、记忆检索、跨Session恢复；短/长流程是独立维度。Harbor是任务组织与运行框架，不是单一场景。
Harness与动作空间Agent能观察和改变哪些工作机制？工具、委派、profile、上下文、记忆、受控插件候选。固定Harness也能训练模型选择管理动作；修改外部Harness代码不自动是RL。
更新对象与参数化究竟改变什么？模型可全参数或LoRA更新；也可冻结模型搜索外部Harness。LoRA不是奖励或学习目标，SFT/GKD/RL均可在适配支持时采用。
训练软件/服务由什么执行梯度与优化？ms-swift、VERL、Tinker是实现/服务选择，不是学习方法。接入支持、概率与token合同必须分别核验。
执行环境与资源工具在哪里运行、GPU在哪里？本地/云端Docker、可选Modal Sandbox；推理与训练GPU可另行部署。环境不决定SFT或RL。
调度与评估如何组织计算，如何认定有效？同步/全异步属于调度；开发/验证/最终测试及预算是实验协议。全异步不等于更强的学习算法。

RLAgent尝试修复，任务测试/评分提供奖励不一定，测试可评分是

LoRA RL用奖励训练LoRA参数不一定是RL与参数化方式的组合
Tinker通过训练API提交训练计算取决于方法服务/工具，本身不是算法

Teacher/student描述指导者和学习者的角色，不要求“父子继承”关系；不同tokenizer或输出空间会带来具体蒸馏对齐限制，不能因为角色成立就假定接口可直接互通。

OPD的两条更新路径

直接分布损失

学生采样访问状态，教师提供分布，直接优化KL/JSD等差异。GKD可以采用on-policy、数据集或混合采样，不能把GKD与OPD当完全互斥方法。

教师信号进入RL

利用教师对采样动作的概率等构造学习信号，以policy-gradient等机制更新。不同实现对概率、mask与baseline要求不同；“teacher给了建议”不足以证明实现这条路径。

上述实现区分已核对ms-swift蒸馏文档。这只是概念依据，不意味着当前Uni-Agent DSH adapter已经支持；它目前仍拒绝teacher_client。

实验学习/采样场景/Harness更新与部署
DSH示范SFT合格教师轨迹 + SFT固定DSH工具合同，学习操作与恢复4B LoRA；离线数据adapter待验；无需Modal

每份实验配置至少写清上述维度与精确版本，比较时明确改变了哪一维。算法、场景、Harness和云服务同时变化会让收益无法归因。

06 · 学习方法与记忆/上下文

SFT / 教师辅助

按真实缺口学习高质量DSH示范与恢复行为。教师轨迹需执行验收；纠错SFT不自动叫OPD，线上教师帮助与学生独立成绩分开。

任务与Harness RL

学生选择工具、调度、记忆/上下文动作，依据后续任务结果更新策略。先终局奖励，再评估树分支或延迟信用，不先实现所有算法。

复用Uni-Agent MemAgent的4B训练recipe和多context能力，但不在DSH外再包一套执行循环。ContextPilot贡献动作前观测、事实保真、A会话写入→B新会话检索及后续奖励。单纯压缩更多token不是成功指标。

任务内长循环、跨会话记忆链、采样/更新训练循环与候选演化循环分别记录身份。ContextPilot树分支partial rollout与全异步调度中的partial rollout不是同一机制。

07 · RSI 是模型行为与版本化外循环

策略层Harness RL训练4B会使用、选择和调整工作方式；慢速RSI循环训练/验证它能提出并利用持久改进。外部强模型搜索可做教师或对照，不能代替学生自主证据。

  1. R0：验证真实执行与隔离基础。
  2. R1：先测有用技能的发现、调用、遵循和不适用时拒用。
  3. R2：固定模型，完成一个窄候选的独立测试、新进程复用和回滚。
  4. R3/R4：学习改进过程，检索原始失败与成功经验，多轮跨任务积累。
  5. R5：单独测改进机制本身在新任务分布上的同预算搜索效率。

沿用Meta-Harness证据检索、DGM档案分级、Self-Harness窄改动；对联合模型/Harness更新做2×2归因。最终封存集不进入候选筛选。详见RSI规划。
