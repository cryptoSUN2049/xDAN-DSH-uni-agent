跨仓库职责与项目长期记忆

两个闭环，分别证明

模型学习闭环

固定 DSH / Harness → 学生执行 → 可信反馈 → SFT / 蒸馏 / RL → 新模型 → 独立评估。

验收：更新后独立加载，在相同预算与未见任务上提高完成率，同时报告成本与回归。

Harness 演化闭环

固定模型 → 分析失败 → 生成隔离候选 → 开发集筛选 → 独立验收 → 晋升或回滚。

验收：Harness 改进能在新进程与新任务上复现；模型与 Harness 收益分别归因。自动搜索不自动等于强化学习。

后期可交替优化模型和 Harness，但需保留原模型×原 Harness、新模型×原 Harness、原模型×新 Harness、新模型×新 Harness 的对照。不能把组件齐全写成 RSI 已实现。

学习方法按能力缺口选择

  • 教师 SFT：收集真实执行且通过验收的 DSH 示范；补工具语义、执行约定、调试与错误恢复。已掌握的基础能力可跳过专项训练，保留回归评估。
  • 学生状态上的教师辅助 / OPD：学生自己 rollout，在实际状态上引入教师信号。纠错轨迹再 SFT 与严格 OPD 分开标记；教师分布可用性、损失、token 对齐和训练入口尚待设计核验。
  • 任务 RL：复用现有 VERL / Gateway 底座，用真实任务奖励优化执行。GRPO / DAPO 等方法需同预算对照，不为制造奖励差异改动验收器。
  • 运行时借力：强模型协助可提高系统成绩，但必须与学生无辅助成绩分开报告，并计入教师成本。

SFT、OPD、RL 是候选方法，不要求首轮全部启用；本项目尚未完成新增 SFT / OPD 路径验证。

最短闭环与完整路线

  1. 基础恢复：固定可复建 DSH runtime、模型、工具与验收版本；保留现有八类真实 smoke 门槛。
  2. 本地单任务：Harbor + Docker oracle 正反例、产物和清理；随后同一环境换成 DSH + Gateway，取得学生真实执行证据。
  3. 数据准入：绑定 task / trial / session / policy version、token / mask / logprob 和 fresh reward receipt；拒绝不合格轨迹。
  4. 小规模学习：基线诊断后选择必要的 SFT / 教师辅助 / RL；完成参数更新、checkpoint 保存和独立加载。
  5. 独立能力评估：相同 token / 时间 / 工具预算下比较未参与训练和筛选的任务；Terminal-Bench 最终测试成绩不能反复用于候选选择。
  6. 云端与吞吐：用 Harbor Modal provider 验证同一任务，解决 Gateway 可达性与清理，再扩大并发和全异步。Modal 与训练 GPU 可分处部署。
  7. Harness 演化：限定候选修改范围，独立验收、晋升、回滚，再研究模型与 Harness 交替优化。

最短路径先完成本地真实执行→学习→评估，Modal 不阻塞本地验证。完整交付包含云端迁移与 Harness 闭环；各项以实际证据逐项关闭。
