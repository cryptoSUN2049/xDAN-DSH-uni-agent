# 面向任务的专家级记忆与上下文管理

2026-09-09。用户澄清后的能力目标；现有任务只覆盖部分基础操作，不代表下述全部实现。当前训练主线，异步/Harbor暂后置，SFT不在本轮范围。

## 目标

让4B模型在DSH唯一执行循环内，按任务需要维护工作状态，选择何时保存、检索、更新、卸载与压缩，在长任务和新会话中可靠继续。handoff/task/goal/memory/index是可选载体，不以文件数量或压缩token数奖励。短配置题是训练起点，不是终局。

| 维度 | 行为 | 后续效用证据 |
|---|---|---|
| 选择 | 区分约束、证据、假设、决策、待办与噪声 | 必要事实保留，推测不变成事实 |
| 保存 | 临时工作状态与长期知识分开，建立可达入口 | 新会话能找到当前步骤所需材料 |
| 检索 | 按需展开原始证据，控制重新载入规模 | 成功读取相关来源，避免全量回填 |
| 更新 | 根据作用域、权威、版本处理冲突和失效 | 最新适用事实驱动正确结果，旧证据仍可追溯 |
| 压缩 | 保留目标、约束、进度、证据位置与未知项 | 实际上下文缩减/切换后继续成功；无真实机制则标未覆盖 |
| 克制与停止 | 简单任务不滥建记忆，完成后停止重复整理 | 不必要写入/重复读取少且不降低成功率 |

```mermaid
flowchart LR
 O[观察任务与上下文压力] --> D[决定保存/检索/更新/暂不操作]
 D --> A[DSH真实文件与工具动作]
 A --> F[冻结实际工件与证据]
 F --> B[新会话或真实上下文切换]
 B --> T[检索/验证/继续任务]
 T --> V[独立任务结果与事实审计]
 V --> R[在线轨迹/奖励/VERL更新]
```

## 分阶段场景

1. 工程续作：需求变更、配置、依赖计划、已完成事项、交接与恢复。先复用WS01/03/05，保留WS06无需记忆负例。计划工件校验不声称真实数据库迁移。
2. 调试：记录已验证/否定假设、实验输入输出与未决问题，恢复后避免重复失败尝试。需新可执行任务，当前尚未生成。
3. 研究：来源及冲突证据、推论与不确定性、引用可追溯。需独立数据划分及可验证产物，当前尚未生成。

场景中的管理原则相同，但具体记忆结构不强求一致。跨场景泛化需独立测试，不能从一种配置题推断专家级能力。

## 奖励和验收原则

主要奖励绑定恢复后的真实任务正确性；记忆完整/检索/事实保真/成本作为诊断分项。若引入过程奖励，先版本化设计并防止通过写更多文件刷分，不能静默修改旧二值奖励。必须区分“管理决策正确→动作成功→后续有效”。

成功指标：任务成功率、关键事实保真、冲突处理、重复劳动、恢复成本与约束违规。不能仅以文件存在、模型自称记住、token压缩率或GPU忙碌作能力验收。

四类循环身份分别保存：任务内long loop、跨会话memory链、采样/参数更新循环、RSI候选演化循环。ContextPilot树分支与VERL异步partial rollout不是同一机制。
