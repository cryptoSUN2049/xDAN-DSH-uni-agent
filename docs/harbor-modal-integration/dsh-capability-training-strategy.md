# DSH 能力内化：从示范到真实任务强化

## 目标

让 Qwen3-4B 在固定 DSH 0.1.3-alpha.2 上，根据当前运行时证据正确发现、选择、组合、修复与清理能力，并在预算内完成业务任务。能复述架构不等于能调度；知识问答只作为辅助诊断。实时工具清单、状态和用户事实仍从运行时读取，不烙入参数当作永恒事实。

## 训练对象与顺序

| 能力 | 任务 | 首选学习信号 | 验收 |
|---|---|---|---|
| 架构与 API 基础 | 区分 Plugin/Package/Run、Tool/Service、生命周期、Session v2 | 源码核实的简短问答 + 真实操作示范 SFT | 解释正确；实际参数、实例身份、接口合法 |
| 能力发现与节制查询 | T1 根据清单查询当前 Tool，避免无关大目录 | 成功示范 SFT；有成功探索后使用 RL | 查询目标正确、答案有证据、预算内完成 |
| 注册与组合 | T2 注册参数化日志筛选/脱敏工具，多输入调用并清理 | 验证通过的完整轨迹 SFT → 业务奖励 RL | 独立 oracle、真实工具调用、生命周期与隐藏输入 |
| 故障恢复 | T3 定位依赖问题、同实例修复并恢复业务 | 成功恢复轨迹 SFT → 故障变体 RL | 有序状态迁移、真实功能恢复、无假成功 |
| 上下文与记忆 | T4 事实保真；T5 A 写入→B 新会话检索 | 真实跨阶段示范 + 任务结果/事实约束奖励 | 新会话身份、因果对照、事实准确；非 token 压缩率 |
| 受控自改进 | T6 提出 Harness 候选、验证、选择或回滚 | 候选评估示范，之后考虑外层搜索/RL | 独立留出收益与成本约束，验证器不可自改 |

## 数据与学习方法

1. 架构文档作为出题与核实来源；每条数据记录 DSH commit、runtime、任务和验证器版本。不要把整站 HTML 直接当高质量操作数据。
2. 示范必须在固定 runtime 真正执行，保留观测、动作、结果、失败恢复和任务结局。人工设计或教师生成都需要独立验收，不允许编造工具结果。
3. SFT 学习模型应输出的动作和回答；工具返回作为上下文而非模型生成目标。训练 mask 与 tokenizer/chat template 必须检查。可用 LoRA，但 LoRA 不是另一种学习目标。
4. RL 由当前学生策略重新采样，通过 Gateway 保留真实 token/logprob，再由独立验证器评分、VERL 更新。离线成功轨迹不能冒充当前策略的 on-policy rollout。
5. 先按任务结果与必要约束判定，再考虑工具调用成本；不要奖励单纯多调用 DSH 或多写反思。基础设施错误单列，不混入模型业务失败奖励。
6. 教师纠错或 OPD 为可选增量。只有文本答案的 API 不等同于具备完整 teacher 概率分布的蒸馏；具体路线需按可获得信号另定，不是 G1 前置。

## 评估与停止条件

- 同预算比较未训练模型、SFT 模型、SFT+RL 模型；先保证工程闭环，随后扩大样本检查效果。
- 训练/开发/最终留出按任务模板、数据和故障组合隔离；仅换文件名不算泛化测试。接口名称变化必须是合法的 runtime fixture，不能虚构 API。
- 分别报告任务成功率、非法调用、错误对象选择、上下文耗尽、清理失败、事实准确率和工具调用/token 成本。
- 全失败先判断任务、示范或执行链问题；全相同奖励先检查任务难度与奖励区分度，不人为制造梯度。
- 有限梯度、权重数值变化、独立 reload 证明工程更新；留出收益证明能力提升，两者分开报告。

## 当前真实基线与下一步

T1 `dsh-capability-grounding-r1` 已结束 exit1：模型先获取合法接口清单，但随后选择 Service/listService，而任务要求查询 Tool。约 67,671 字符的结果触发 Gateway 18,432 token 会话容量检查；结果没有纳入上下文，Gateway 合成空输出/length，DSH 标为 max-tokens，严格准入拒绝未完成轨迹，后续空批次报错。这是未完成任务诊断，不是完整评估通过。

源码已核实 max_tokens_per_turn=2048 优先于 max_total_tokens=4096；不能将这次失败归因于累计 4096 上限。新增结果精确 token 数尚未复算。保留失败 baseline，不靠增大预算抹掉错误查询行为。

近期继续完成 T2 的真实 DSH 执行、严格评分与 baseline。若基础动作探索不足，先收集少量通过验证的 T1/T2 示范进行 SFT，再做小批 RL、权重审计、独立 reload 和留出评估。T2 的业务 oracle/公开 fixture 仅为准备工作。Harbor+Docker 后续承载同类任务与独立验收；Modal/全异步留待性能阶段。
