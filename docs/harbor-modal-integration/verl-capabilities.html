先理解各自的位置

Modal 是托管云计算平台，Sandbox 是其中一项服务；它也提供 GPU 计算等能力。Harbor 管任务格式、环境生命周期、Agent 执行与评分。VERL 管轨迹采样与参数优化，Uni-Agent 连接 Agent runtime、模型 Gateway 和训练数据。

VERL 支持调用沙盒，不代表 VERL 自身就是云沙盒服务。Harbor 也不是强化学习优化器。使用 Modal 沙盒，不要求训练 GPU 也部署在 Modal。

当前仓库已经有哪些入口

  • verl/verl/experimental/agent_loop/tool_agent_loop.py：模型生成、工具调用、反馈的多轮循环。
  • verl/examples/tutorial/agent_loop_get_started/sandbox.py：通过 HTTP 调用 Sandbox Fusion；外部服务执行代码。
  • verl/verl/experimental/fully_async_policy/shell/dapo_7b_async_retool.sh：多轮工具 + GRPO + 全异步示例；依赖额外 recipe 文件和沙盒服务，不是单文件即用。
  • examples/quickstart/training/train_qwen3p5_dense.sh：Uni-Agent 的模型训练入口。
  • examples/mini_swe_agent/run_train.sh：外部 mini-swe-agent 的训练入口；当前配置使用 OpenYuanrong，不能直接称为 Harbor + Modal 示例。
  • examples/dsh/train_qwen3_4b_online_rl.sh：现有 DSH 训练入口，调用 verl.trainer.main_ppo；不能仅凭 rollout.mode=async 称它已经全异步训练。

算法、调度、环境是三个维度：GRPO/PPO 决定如何更新参数；同步/全异步决定采样和训练如何排队；Docker/Modal 等决定任务在哪里执行。长流程还要求同一任务中保留文件、进程或 shell 状态，并正确处理超时、上下文压缩、权重版本和评分。

本项目如何跑通

  1. 固定一个任务，用 Docker oracle 验证任务、正确评分、错误拒绝、产物和清理。
  2. 同一个环境换成 DSH bridge，通过真实 Uni-Agent Gateway 让模型完成任务。
  3. 对齐 token、训练 mask、logprob、模型版本与任务评分回执；无效轨迹拒绝进入训练。
  4. 将同一任务迁到 Harbor 的 Modal provider，验证远端网络、文件传递及清理。环境只由 Harbor 创建。
  5. 用现有 VERL 入口做小步更新、保存和独立加载 checkpoint；再做同预算未见任务对照。
  6. 正确性通过后，再扩并发、全异步、长上下文与 Harness 演化。
