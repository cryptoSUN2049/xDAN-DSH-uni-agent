## 1. 主线与旁线

用户确认主线：数据画像筛选 → Curator任务编排 → 教师真实执行 → Verifier验收 → 中立轨迹母本 → 20种子 → 100产线验收任务 → 合格1K Agent SFT。

格式专项独立推进：[apus-chat-v1-tool-call.md](apus-chat-v1-tool-call.md)。后续小实验：中立轨迹母本 → APUS模板渲染 → 格式/mask验证 → 小规模迁移SFT → 工具任务与能力回归。该实验不作为当前数据生产前置；教师使用已验证协议，完整保存原始轨迹。

多harness先落实版本和隔离合同，不同时引入多套复杂运行框架。20题在一个已验证harness上生产，另一个harness作为后续迁移验收，测试轨迹不回流训练。

## 2. 数据筛选三档

以下为优先级，不代表已通过最终准入。来源详见[专题报告](mimo-agent-sft-9b-report.html#data-inventory)及[画像抽查](mimo-agent-sft-evidence/portrait-audit.json)。

| 分档 | 来源或类型 | 下一项必须完成的检查 |
|---|---|---|
| 优先复验 | Open-SWE-Traces、greghavens终端编码母本 | 原文件/版本、会话完整性、成功证据、去作弊、repo/task隔离、许可 |
| 优先复验 | UltraData-SFT-Agent-2609 Office子集 | 角色/tools/mask、上游限制、静态发布物不能冒充可回放环境 |
| 优先复验 | FineEnvs/data-agent-sft | 原HuggingEnvs重定向更新、任务/env可得性、Kaggle源许可、task去重 |
| 优先复验 | Spreadsheet-RL train任务 | 输入/目标工作簿与环境、parser重复、全部评测题隔离；这是生成SFT的环境来源 |
| 有限用途 | Cascade-2-SFT的chat/IF/safety | 子来源分开筛，能力保留，不全部叫Agent轨迹 |
| 有限用途 | 创意写作、Multilingual STEM | 不当商务写作/翻译主料；shadow prompt污染、真实日期与许可逐项审计 |
| 暂不纳入 | 缺工具结果、截断、空参数或品牌搬运集 | 除非原始证据可恢复并重验；不能补造工具反馈 |
| 暂不纳入 | OfficeQA / GDPval / SpreadsheetBench等评测 | 保持评测身份，不能因HF有train分区就放行 |

每个源输出：accept/reject/limited + 原因、上游revision、样本和任务数量、可读完整文件数、许可与评测重叠。S/A评级、文件大小、教师名字不替代准入。

## 3. 20个种子任务规格

本版按用户新增办公/数据处理/翻译/写作重点，将工程试点分为5类×4题；这是对旧“研究/工具/中文”粗分类的细化，不是MiMo比例复刻，也不是最终1K配比。跨工具状态、资料引用、中文约束、失败恢复嵌入各类。最终以能力画像和有效监督token定配方。

所有输入优先自建、授权、确定性生成。不给模型隐藏答案、grader源码或参考产物。模型能读取的材料与评分专用材料必须物理/权限隔离。

| ID | 类别/任务 | 模型可见输入 → 交付物 | 核心Verifier与负例 |
|---|---|---|---|
| O01 | Excel销售汇总 | 两份月份xlsx → 合并工作簿/分组汇总/说明 | 单元格与总额重算；错误币种相加必须不通过 |
| O02 | DOCX会议纪要 | 中文会议记录/角色表 → 决策、行动项、负责人、截止日 | 文档可读+结构检查+事实rubric；虚构负责人失败 |
| O03 | PPTX业务汇报 | 固定季度事实材料 → 有图表与来源的演示稿 | 文件/页数/关键数值/来源；缺失或杜撰结论失败 |
| O04 | 跨文件更新 | 报价xlsx+合同docx+变更说明 → 一致的新版本 | 两文件金额/日期一致、原件保留；仅改一份失败 |
| D01 | CSV清洗 | 含重复/空值/类型冲突CSV → 清洗表+变换日志 | 行数与键约束、无静默删错；错误重复规则失败 |
| D02 | SQL联表 | SQLite多表与指标定义 → SQL+结果表+说明 | 参考查询和边界fixture；一对多重复计数失败 |
| D03 | 时间/单位处理 | 跨时区日志、带单位观测 → 标准化数据与图表 | 时间边界、单位不变量；错日归组/混单位失败 |
| D04 | 数据报告与恢复 | 缺一项可替代依赖的分析环境 → 可复现脚本+报告 | 脚本重跑一致、实际图表与数值；虚报运行成功失败 |
| T01 | 技术文档中译英 | 原文+术语表+数字表 → 翻译文档 | 数字/单位/术语检查+双语抽检；漏译否定词失败 |
| T02 | 商务材料英译中 | 源邮件/说明/人名表 → 中文译文 | 实体/金额/日期一致+语义rubric；增加承诺失败 |
| T03 | 保留结构的翻译 | 含表格脚注的docx → 译后docx | 表格/脚注关系保留+双语检查；漏行失败 |
| T04 | 术语修订 | 源文、已有译文、客户术语变更 → 修订稿+变更表 | 全文一致、未改无关事实；仅局部替换失败 |
| W01 | 基于材料的提案 | 需求、预算、约束材料 → 中文方案docx | 事实引用、预算合计、范围约束；虚构案例失败 |
| W02 | 多轮商务邮件 | 来往邮件+用户修订要求 → 新邮件及说明 | 收件人/承诺/语气/禁用信息；遗忘前轮约束失败 |
| W03 | 证据综合写作 | 固定离线文档包 → 对比报告与引用 | 引用定位、矛盾与不确定性标记；无来源断言失败 |
| W04 | 编辑与结构改写 | 冗长报告+读者/篇幅要求 → 精简稿+修改说明 | 关键事实/数值保留、篇幅约束、人工rubric；删关键风险失败 |
| C01 | Python缺陷修复 | 小型自建仓库+issue → patch+测试结果 | 隐藏边界测试/回归；只通过公开例子失败 |
| C02 | CSV工具实现 | API合同与测试样例 → 可执行CLI | 输入类型/编码/错误码；硬编码样例失败 |
| C03 | 多文件重构 | 自建repo+接口兼容要求 → 重构patch | 行为等价与无关改动检查；改接口失败 |
| C04 | 调试与验证 | 确定性失败日志+自建repo → 修复及复现实录 | 根因修复、测试重跑；只改测试绕过失败不通过 |

注意：翻译/写作没有一个自动分数能完整代表质量。确定性约束+独立盲审rubric+人工抽检联合验收；LLM judge分数不能独自声明“正确”。

## 4. 每题资产包合同

- `task.json`：ID、family、split_group、输入清单、允许工具、成功定义和预算。
- `inputs/`：模型可见文件；内容hash固定。
- `environment`：镜像/依赖/工具版本、reset方法；文件产物可独立打开。
- `grader`：确定性检查、开放rubric、错误分类；参考答案不向模型暴露。
- `controls/`：参考正确、错误、空交付物；infra故障与合法失败必须区分。
- `trajectory/`：真实教师调用、观察、工件、消耗、终止状态；身份与来源完整。

这是拟实施布局，当前尚未生成这些文件或测试结果。

## 5. 教师与预算准入

GPT6-sol作为候选，不根据会话标签猜批量接口。先固定provider、正式model ID、endpoint、返回字段、实际价格、配额与训练用途条件。禁止记录凭证明文。

Curator负责结构化任务生成/批处理与缓存；Uni-Agent/runtime负责真实多轮执行；Verifier独立验收。离线LLM编造完整工具对话不算真实执行。

初始控制建议：最多每题2次、每次20轮；须在启动前补齐总金额、token、wall-time、并发上限。若截断，不放宽后改写原结果；形成新预算版本。当前未冻结总金额，因此不启动计费生成。

## 6. 20 → 100 → 1K 的放行条件

| 阶段 | 实际目标 | 下一阶段放行证据 |
|---|---|---|
| 20种子 | 验证任务、工具、grader与轨迹合同 | 每题正确/错误/空控制；真实执行可追溯；错误与成本分布可解释 |
| 100产线验收 | 增加任务族与边界；测试恢复/去重/并发/费用 | 释放版本可重建；dev隔离；坏样本不会静默入库；达到事先冻结的成本/有效率标准 |
| 1K Agent SFT | 合格独立任务及对应监督轨迹 | 不是1000前缀；按域loss token冻结配方；回归与独立评测准备完成 |

正式模型效果需独立dev/sealed；20/100用于工程和开发，不直接宣称全面提升。Office/翻译/写作与代码的通过率分别报告，不混成无解释平均分。
