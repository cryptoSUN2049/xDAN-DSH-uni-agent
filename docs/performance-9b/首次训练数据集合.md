# Performance-9B 首次训练数据集合与准入方案

版本：v0.2 · 2026-09-23

**当前主目标：全面能力的多领域、多教师在线蒸馏（MOPD）。此前四源SFT＋单教师OPD方案不作为主训练路线；下方原方案保留为辅助数据审计与对照实验参考，不能直接据此启动。**

## 当前生效的 MOPD 约束

- 首先建立 math、code、swe、science、instruction_chat、tool_use 六类domain；安全与中文覆盖作为跨域标签。是否拆成独立domain由教师能力与验证器决定。
- 数据来源身份与教师路由分开保存。官方默认 `distillation.teacher_key=data_source`；如采用 `domain`，须确保该字段在数据加载、DataProto和rollout链路中保留，并与教师配置 `.key` 精确匹配。
- 当前原生路由是每样本选择一个教师，不是多个教师对同一样本自动投票或融合分布。
- 既有数据集先提供任务、提示、环境与验证依据；静态专家回答不是学生on-policy轨迹。各域数据均须通过既定质量门禁。
- 官方文档明确要求教师与学生共享tokenizer和词表；当前代码直接传递学生token IDs。同族名称不等于自动兼容；原生实现不能直接接入不同tokenizer的异族教师。
- 闭源API若只返回生成文本，不能直接接入当前token级MOPD。需要任意学生续写的逐token评分、位置/token对应；top-k损失还需要兼容词表的top-k分布。
- 闭源模型可用于离线数据生成、批改与judge，但这些功能不能冒充原生在线MOPD。跨tokenizer/黑盒蒸馏需要单独算法与接口设计验收。
- 六个domain不强制六个教师；先用两个兼容且经过领域能力验证的教师做多域pilot，覆盖六域与分域验证。单教师probe只作链路验收，不计为多教师目标完成。
- 双卡多教师驻留或轮换方案尚未验收，禁止把轮换视为现成支持或同时启动占满资源。
- 下一项必需交付：domain→来源子集→教师→评分接口→验证器映射及真实tokenizer兼容性测试，之后再冻结条数/比例。

依据：[VERL OPD官方文档](https://github.com/verl-project/verl/blob/main/docs/algo/opd.md)；本地 `verl/verl/experimental/teacher_loop/teacher_manager.py` 与 MOPD FSDP example。本文尚无新数据构建或多教师训练完成的证明。

## 原 v0.1 辅助方案（主路线已由上文替代）

## 1. 首次训练的目标与边界

- 学生：现有 Qwen3.5-9B 起点；实际启动时必须记录模型仓库、revision、tokenizer 和 chat template，确认是否为 base/instruct，不能仅凭目录名判定。
- 在线 OPD 教师：现有 Qwen3.8-27B；同样记录 revision 和模板。
- 首先完成既定 9B＋27B OPD：真实生成 → 教师评分 → 非零参数更新 → checkpoint 保存 → 重载 → 固定预算验证。
- 数据升级实验：独立建立小规模精选 SFT 对照，验证软件工程、数学、科学、通用交互是否改善。**SFT 不替代已授权的 OPD 验收；不能把两者串联后只测最终模型。**
- 首轮不做大规模 mid-training，不做多教师同时驻卡，不从零预训练。
- 两张 GPU 的可行配置、序列长度和耗时须通过显存与吞吐探针确定。不能把本方案视为硬件容量保证。

## 3. 首轮 SFT 配比：6,000 条起步，按 token 校正

先构建小版 `xDAN-9B-SFT-QualityMix-v0.1`，候选记录目标如下。它是待构建的名字，不是已存在的 HF 仓库。

| 能力 | 目标条数 | 比例 | 具体选择 |
|---|---:|---:|---|
| SWE | 1,800 | 30% | 成功且工具结构完整的轨迹；Python/JS/TS为主，保留少量其他语言，记录实际比例 |
| 数学 | 1,500 | 25% | 按难度和题型分层，每题优先一个完整正确解答 |
| 科学 | 900 | 15% | 物理/化学/生物各300条，优先有明确正确性依据的题 |
| 通用聊天 | 900 | 15% | 简洁、事实可靠、有用，不能只按长答案或judge偏好选取 |
| 指令遵循 | 750 | 12.5% | 多约束、格式、多轮保持，优先可以程序检查的要求 |
| 安全与合理拒答 | 150 | 2.5% | 包含合理回答与合理拒答，检查误拒答 |
| **合计** | **6,000** | **100%** | 以上为通过质量门禁后的目标，不足不凑数 |

**长度与预算：**

- 先跑总序列长度 4K 的吞吐/显存探针；8K 作为后续探针候选，未经测量不承诺。
- 用学生 tokenizer 计算长度，不能使用网页字节数估计实际训练 token。
- 首轮 SFT 全部训练样本总输入 token 暂设上限 24M，同时统计 assistant 目标 token；达到任一预算边界即停止扩充。
- 条数比例不等于梯度贡献。记录各域总 token、assistant 目标 token、thinking/action/final token；单域目标 token 暂不超过总量40%。
- 超长轨迹不直接尾截断；完整短轨迹不足则减少 SWE 数量并记录覆盖缺口。不要人为拼接工具结果、最终答案或思考尾部。
- 这些限制可能偏向短任务，所以不能据首轮结果宣称长程 SWE 能力已提升。

## 4. 首轮 OPD：独立且可诊断

候选派生集：`xDAN-9B-OPD-Math-Pilot-v0.1`。

- 训练题128道、开发验证64道、最终保留64道；按题目身份和近重复簇拆分，而不是按回答行拆分。
- 所有题必须与 SFT 数据、原有验证集和新保留集联合去重；发现重叠则移除训练侧样本。
- 第一步使用2道训练题做真实更新/保存/重载冒烟，再进入有固定验证间隔的短程实验；完整训练步数由吞吐探针和验证结果确定。
- 学生在线生成，27B教师在相同上下文对学生 token 评分。已有静态教师答案用于验真/参考，不伪装成 on-policy 轨迹。
- 首轮保持单教师；多教师、工具型 OPD 和 RLVR 分别做后续消融，不同时引入多个变量。
- 基线0步及每5个训练步做同一开发集、同一推理预算的验证。最终保留集只在候选冻结后使用。
- GRPO有效组比例适用于使用组相对任务奖励的 RL 分支；**不能因全对/全错就推断纯OPD没有蒸馏信号**。纯OPD另看有效评分token、师生logprob差、梯度和真实参数变化。

## 5. 必须隔离的验证数据

SFT 额外准备600条开发验证、600条最终保留，按上表比例分层；都不包含在6,000条训练目标中。若无法满足，则缩小试验并如实记录。

- SWE：优先按 repository 分组；若规模不允许，至少按 issue/PR/instance_id 分组，并报告存在同仓泛化的限制。
- 数学/科学：相同题、翻译版、数字微改写、同一源URL题族不得跨拆分。
- 多轮/工具：同一 trajectory_id、原始任务和其切片不得跨拆分。
- 新数据与已有 eval-set-v1、TB2.1、SWE-bench Verified 任务清单比对；若暂时没有完整清单，不能宣称污染检查通过。
- 通用能力保留集覆盖中文/英文、短回答、写作、事实性和拒答；此项目前仍有数据缺口。
- teacher评分不能兼任唯一最终裁判。代码看测试，数学看独立答案验证，开放问题用校准后的rubric和抽样人工复核。

## 7. 其他暂不混入的数据

- **Nemotron-SFT-SWE-v3.5**：保留替代来源；先澄清卡片用途表述和验证证据，避免与Open-SWE-Traces重复。
- **Agentic-v2、Competitive-Programming-v2、Chat-v2**：有用的补充候选，但不为追求数量再加入首轮；直接使用前核对来源、重复、占位内容与质量。
- **Function-Calling-Pivot-v1、Terminal-Pivot-v1**：专项阶段再接入。动作匹配奖励与真实任务成功不同，需要环境状态和动作语义验证。
- **RL-Science、InverseIFEval、Multichallenge**：待judge校准和9B难度探测，避免再次出现大多数组无有效任务奖励差异。
- **Pretraining-Specialized-v1.2**：作为后续mid-training消融；先抽查事实性，不与首轮SFT混为一个实验。
- **CC、Legal、Pretraining-Code-v3**：先不采用；Code-v3是元数据，仍有源码恢复成本。
- **Cascade全量、其他Post-Training全量blend**：不直接照搬大模型的配比、256K长度或训练轮数。
- **Math-Proofs、VLM、Personas、Finance**：分别属于证明、多模态、合成种子、垂直领域专题，当前首轮不扩范围。
- **已归档第三方MOPD四域集合**：继续归档，不进入首轮；先完成上游来源和跨集合重叠审计。
- **已归档OpenThoughts-Agent-RL-5K**：保留后续可执行RL任务池，先完成环境/verifier验收。

## 8. 从候选到可训练数据的硬门禁

每个来源先抽样200条审查，安全子集不足200则全查。这只能作为筛查，不能据此宣称全库可靠。

1. 固定源revision，保存原始文件哈希、原始路径、逐样本来源和许可证；派生仓库不覆盖原始归档。
2. 全量schema检查；空题、缺答案、缺工具结果、异常编码、截断示范不入选。
3. 按题目与任务分组去重，完成跨来源和评测污染检查。
4. 代码抽样复跑测试；数学独立复核答案；科学核查参考依据；聊天/安全样本按明确rubric审查争议项。
5. 学生模板渲染往返检查；assistant目标mask正确，工具观察不作为输出目标；thinking结构不丢失、不伪造。
6. 首批对每域做难度探测，记录9B正确率、长度、超时和错误类型；不依赖教师总体强度推断数据适配性。
7. 保存质量报告、排除清单和实际分布；抽检发现系统性问题，整来源暂停，不只删掉被发现的几条。
8. 通过后才将状态从 `candidate` 改为 `ready_for_pilot`；真实训练验证通过后才可进入扩大实验。

派生样本最少保留：sample_id、source_repo、source_revision、source_record_id、split、domain、license、teacher（未知填unknown）、verification、token_counts、content_sha256。训练配置记录seed、模板hash、数据manifest hash、环境与verifier版本。

## 9. 验证与自动暂停闭环

以相同预算下的独立验证为准，不能只看训练loss下降。以下为首次实验建议阈值，必须随启动配置固化：

- 出现NaN、无有效rollout、评分器失效、checkpoint重载失败：立即暂停，不能记为能力0分。
- 在相同开发集上连续两个验证点，主指标比基线下降至少5个百分点：暂停检查并做配对统计；阈值触发本身不等于统计显著。
- 中位输出token超过基线1.25倍、同时正确率没有改善：暂停检查；超时率上升至少5个百分点亦触发检查。
- 开放题judge大量分歧、thinking/action解析异常、训练/验证题泄漏：暂停对应数据来源。
- 同时记录平均与P95长度、截断率、超时、工具调用次数、每个成功任务成本。
- 对RLVR分支记录有效组比例；对OPD分支记录评分覆盖、梯度和checkpoint参数差异。
- 固定验收：起点模型、SFT候选、OPD候选分别比较；若增加SFT→OPD串联，再增加一个独立实验臂。

## 2026-09-24：现有教师资源下的实施决策

- 用户提供的资源条件：现有27B开放教师，以及Fable/Opus/GPT来源的高质量静态SFT数据；更大教师后续再考虑。型号可用性、来源身份与硬件需求未在此核验。
- 原生VERL MOPD要求共享tokenizer/vocab，不存在已验收的跨tokenizer直接插入路径。
- 静态异族示范可转为学生模板并进行离线SFT；不能转成未曾取得的教师在线logprob。
- 推荐先做27B与9B起点在各域固定验证上的对照，再决定27B是否值得当教师。
- 若需要真实多教师：用审计后的不同领域示范，从同一个兼容开放底座训练领域adapter/checkpoint，验证各域收益及保留能力后选教师。它们是闭源知识的中间代理，不能宣称等同闭源教师能力。
- 以少量域试验比较：原始学生、精选SFT学生、单27B OPD学生、多领域专家MOPD学生；教师训练、学生训练、最终保留任务分组隔离。
- 27B专家适配和双卡多教师服务均是待设计验收工作，不能假定多adapter prompt-logprob或轮换已经支持。
- 若拿不到强于基线且相互互补的领域专家，保持多域单教师OPD；不能仅改路由名或prompt冒充MOPD。
