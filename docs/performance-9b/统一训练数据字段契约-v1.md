# APUS 统一训练数据字段契约 v1

状态：冻结字段设计；当前screened-v2仍为中间产物，尚未迁移并通过此契约验收。版本标识 `apus-sft-v1`。本文件为HF统一母本的列名/类型权威入口；覆盖旧文档的拟议字段名，不改变不可改写的原始归档。

## 三层数据

1. **原版归档**：保留上游原文件和columns，不强制统一，不覆盖。
2. **统一文本SFT母本**：以下27个固定顶层columns；含来源和准入证据，供HF保存、筛选、去重、审计。字段缺失明确null/unknown，不能伪造。
3. **训练导出**：从同一个冻结task manifest生成ms-swift/VERL视图；仅把模型输入与监督合同交给训练器，不把来源、评分和教师标签拼进提示。

APUS协议名 `apus-chat-v1` 与数据版本 `apus-sft-v1` 不同：母本不绑定MiMo/Qwen模板，模板ID及tokenizer revision记录在训练导出manifest中。

## 固定顶层columns

所有列必须存在；允许null的列以下明确列出。JSON string是可解析的标准JSON，不是Python repr。

| Column | Arrow/HF存储类型 | 含义与规则 |
|---|---|---|
| `schema_version` | string | 固定 `apus-sft-v1` |
| `id` | string | 唯一样本ID；由固定来源revision、文件和行标识确定，不随导出模板改变 |
| `task_group_id` | string | 全池联结后的任务组件ID；同源任务、跨源相同任务不得跨split |
| `split` | string | train / validation / test / quarantine / excluded；validation为内部dev标准名 |
| `domain` | string | code / reasoning / office / data / translation / writing / general / unknown；唯一主域 |
| `capabilities` | list<string> | 多标签能力，如swe、proof、spreadsheet；无证据时空数组，不当作互斥分布 |
| `language` | string | zh / en / mul / ru / unknown等标准语言码；检测不确定时unknown，不由西里尔字符直接断言ru |
| `teacher_model` | string nullable | 原始教师型号声明；未知null，不能靠数据集标题覆盖冲突字段 |
| `teacher_family` | string | 当前qwen38 / fable / gpt56 / gemini31 / other / unknown；具体型号仍保留teacher_model |
| `teacher_evidence_json` | string | 证据来源、全部原始声明、冲突及核验状态；row_claim/publisher_claim不是独立鉴真 |
| `source_repo` | string | 直接读取的原始HF库，不是我们的派生库 |
| `source_revision` | string | 完整固定commit hash；不能为main/latest |
| `source_file` | string | 原库相对文件路径 |
| `source_row` | int64 nullable | 0-based原始行号；多事件重建时null，完整事件映射放provenance_json |
| `source_record_id` | string nullable | 原库样本/事件ID；没有则null |
| `source_task_id` | string nullable | 原始session/trajectory/task标识；标识字段与来源范围写入provenance_json |
| `source_split` | string nullable | 上游原始split，保留原字符串，准入时归一val/dev等别名；未知null |
| `source_license` | string nullable | 上游声明许可，未知null；不是对再发布权利的自动保证 |
| `source_file_sha256` | string | 64位hex，绑定不可变原文件；多事件跨文件时主文件hash并在provenance中列全文件 |
| `messages` | list<fixed struct> | 结构化消息；见下方固定子字段 |
| `tools_json` | string nullable | JSON数组形式的工具定义。`[]`表示明确无工具；null表示定义未知，不能混同 |
| `supervision` | fixed struct | 监督模式、目标message ID、thinking策略；不依赖易变数组索引 |
| `quality_status` | string | unreviewed / structurally_screened / training_ready / quarantined / excluded |
| `quality_flags` | list<string> | 原因码，包括结构、来源、语言、污染、预算等；无异常为[] |
| `provenance_json` | string | 原始引用/事件映射/教师继承/修复历史/域与语言标签证据/去重组件关系 |
| `stats_json` | string | 统计及计算器版本；未知token量为null，不能把字符数当token数 |
| `content_sha256` | string | 规范语义内容hash（messages、tools及supervision），不含source/status以支持跨源去重 |

`quality_status`与`split`正交：例如验证集也可能只是structurally_screened。训练必须同时满足split=train、quality_status=training_ready和全部gate；不能只凭split选择。

## messages 固定子结构

每条消息都包含以下字段；不适用的标量为null，tool_calls为[]：

```text
message_id: string
role: string                       # system / user / assistant / tool
content: string nullable            # 空字符串与null保留区别
reasoning_content: string nullable  # 仅真实上游thinking；缺失不补写
name: string nullable
tool_call_id: string nullable
tool_calls: list<struct<
  id: string,
  type: string,                     # function
  function: struct<
    name: string,
    arguments: string              # 严格JSON对象字符串
  >
>>
```

示例为结构示意，不是训练样本：

```json
{
  "message_id": "m2",
  "role": "assistant",
  "content": null,
  "reasoning_content": null,
  "name": null,
  "tool_call_id": null,
  "tool_calls": [{
    "id": "call_001",
    "type": "function",
    "function": {"name": "add", "arguments": "{\"a\":137,\"b\":286}"}
  }]
}
```

工具结果为role=tool，tool_call_id必须对应真实调用，content保留真实观察。禁止猜造调用和工具输出。无工具定义/调用ID的上游轨迹保留原版并隔离；不能仅为了满足schema填造。

### 为什么工具参数和定义用JSON string

不同工具的arguments键和parameters schema不同。直接写成任意Arrow struct会产生不断增长的字段、类型冲突，且null与缺失容易失真。**校验时解析成JSON对象；母本物理存储时使用严格JSON字符串；目标模板需要对象时由导出器再解析。** 工具定义单独叫tools_json，避免同一列一会是list一会是string。

拒绝重复JSON键、NaN/Infinity、不闭合JSON；不自动补括号/参数。验证JSON对象不能只看json.loads成功，还要验证该工具schema。旧normalize.py里的arguments对象属于中间内存形态，不能直接宣称已符合母本。

v1只验收文本SFT。原始多模态content blocks及未知消息扩展仍保留原版；不得扁平化丢掉图像等信息后静默纳入v1。

## supervision固定子结构

```text
mode: string                       # all_assistant / selected_assistant
message_ids: list<string>          # 非空；全部需要监督的assistant消息ID
reasoning_policy: string           # include / exclude / unresolved
```

- all_assistant也必须显式展开目标ID，避免不同框架各自推断。
- 从上游target_message_index转换为稳定message_id；先生成原始ID映射，再转换/合并消息。
- 用户、system、tool结果永不监督；历史assistant是否监督由这里决定。
- reasoning_policy=unresolved不允许训练；缺失reasoning不能伪造，也不能将最终答案错误塞进thinking。
- 是否监督工具边界/EOS由固定导出合同和真实token-mask测试决定；不能在母本伪造token位置。

## 派生训练视图

| 视图 | 导出内容 | 不变约束 |
|---|---|---|
| ms-swift SFT | messages、tools及精确assistant loss/labels映射；具体role转换固定适配器版本 | 同一任务split/目标消息；MiMo原生模板首次验收 |
| VERL SFT | messages、tools、目标消息映射；custom_cls产生loss_mask | 不把默认全assistant监督当成已支持target-only |
| OPD/RL | 另定义prompt/domain/task_env/verifier等schema | 不把教师答案改名当在线rollout；本v1是SFT母本 |

母本不插入APUS身份system、不替换MiMo/Qwen品牌词。APUS产品策略及模板迁移是独立实验变量。
